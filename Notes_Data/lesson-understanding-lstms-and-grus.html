Lesson: Understanding LSTMs and GRUs

Introduction

In previous lessons, we learned how Recurrent Neural Networks (RNNs) use a hidden state that is passed from one time step to the next to process sequences. While RNNs can, in theory, learn relationships across arbitrary time steps, they struggle in practice to retain long-range dependencies due to a challenge known as the vanishing gradient problem.

This problem causes earlier inputs in a sequence to have little to no effect on model updates during training. As new inputs are processed, earlier context is overwritten, making it hard for RNNs to “remember” information over many steps.

To overcome this, Long Short-Term Memory (LSTM) units and Gated Recurrent Units (GRUs) were introduced. These architectures incorporate gating mechanisms that regulate how information flows through the network allowing relevant data to be retained and irrelevant information to be forgotten.

In this lesson, we’ll examine LSTMs and GRUs in detail, how they work, how they solve the vanishing gradient problem, and how they compare in practice.

Learning Outcomes

By the end of this lesson, you will be able to:

  1. Explain how LSTM and GRU architectures address the vanishing gradient problem.
  2. Compare the gating structures of LSTM and GRU units.
  3. Apply LSTM/GRU-based sequence models to solve NLP tasks involving long-range dependencies.

Recap: Why Vanilla RNNs Fail

Before diving into gated recurrent architectures, it's worth briefly recalling why vanilla RNNs fall short on long sequences. Standard RNNs struggle to retain information over many time steps due to the vanishing gradient problem. As gradients are backpropagated through time, they often shrink to near-zero making it difficult for the model to update weights associated with earlier inputs. This limitation prevents RNNs from effectively modeling long-term dependencies, especially in tasks like language modeling, translation, or speech recognition, where important information may appear far from where it is needed.

To overcome this, researchers introduced new recurrent architectures LSTMs and GRUs designed specifically to preserve information and gradients across long sequences.

Understanding LSTM Architecture

The Long Short-Term Memory (LSTM) network was introduced by Hochreiter and Schmidhuber in 1997 to address a key limitation of standard RNNs: the inability to retain long-range dependencies due to vanishing gradients. LSTMs solve this by modifying the structure of the recurrent unit itself adding internal gating mechanisms and a separate memory state that allows for better control over what information is remembered or forgotten over time.

Core Design: The Cell State

At the heart of the LSTM is the cell state \(c_t\), which acts as a form of long-term memory. It is passed from one time step to the next with only minor linear interactions, allowing information to flow relatively unchanged. The model decides what to store, update, or discard using three gates:

  • Forget gate \(f_t\): Decides what information to remove from the cell state.
  • Input gate \(i_t\): Determines what new information to write to the cell state.
  • Output gate \(o_t\): Controls what part of the cell state is passed to the hidden state.

Instead of relying only on the hidden state like vanilla RNNs, LSTMs separate short-term and long-term memory via:

  • a hidden state \(h_t\)
  • a cell state \(c_t\)

The network learns to control these two through three gates.

LSTM Equations

At each time step \(t\), given input \(x_t\) and previous hidden state \(h_{t-1}\), the LSTM performs the following operations:

New Content : new content to be written to the cell

\[ \begin{aligned} ĉ_t &= \tanh(W_c \cdot [h_{t-1}, x_t] + b_c) \\ \end{aligned} \]

Forget Gate: Controls what portion of the previous cell state to keep.

\[ \begin{aligned} f_t &= \sigma(W_f \cdot [h_{t-1}, x_t] + b_f) \\ \end{aligned} \]

Input Gate: Controls what new information to add to the cell state.

\[ \begin{aligned} i_t &= \sigma(W_i \cdot [h_{t-1}, x_t] + b_i) \\ \end{aligned} \]

Cell State:

  • erase (“forget”) some content from last cell state
  • write (“input”) some new cell content
\[ \begin{aligned} c_t &= f_t \cdot c_{t-1} + i_t \cdot \tilde{c}_t \\ \end{aligned} \]

Output Gate and Hidden State:

  • Output Gate: Controls what part of the cell state is exposed as output.
\[ \begin{aligned} o_t &= \sigma(W_o \cdot [h_{t-1}, x_t] + b_o) \\ \end{aligned} \]
  • Hidden State: read (“output”) some content from the cell
\[ \begin{aligned} h_t &= o_t \cdot \tanh(c_t) \end{aligned} \]

Here,

  • \(\sigma\) is the sigmoid activation function.
  • \(\tilde{c}_t\) is the candidate cell state.
  • \(h_t\) is the hidden state (used for output or passed forward).

Gradient Preservation

The key to the LSTM’s success lies in its additive update to the cell state:

\[ c_t = f_t \cdot c_{t-1} + i_t \cdot \tilde{c}_t \]

This structure allows gradients to flow back through time without being repeatedly scaled by small numbers, as long as \(f_t \approx 1\) and \(i_t \approx 0\). In other words, the cell can retain information across many time steps without degradation.

The LSTM cell introduces controlled memory and selective information flow enabling effective long-term learning in sequential models.

While LSTMs are powerful and widely used, they are not the only solution to the vanishing gradient problem. A simpler and more computationally efficient variant, the Gated Recurrent Unit (GRU), was later proposed to achieve similar results with fewer parameters. In the next section, we’ll explore how GRUs differ from LSTMs and when one might be preferred over the other.

GRU Architecture

While LSTMs successfully addressed the vanishing gradient problem, their complexity, particularly the use of three gates and a separate cell state, motivated the development of a more streamlined alternative. The Gated Recurrent Unit (GRU), introduced by Cho et al. in 2014, simplifies the LSTM architecture while maintaining its ability to learn long-range dependencies.

GRUs achieve this by merging the cell state and hidden state into a single vector and reducing the number of gates from three to two. This makes GRUs computationally lighter and easier to train, particularly on smaller datasets or in low-latency environments.

Core Design: Fewer Gates, Unified Memory

Unlike LSTMs, which maintain two internal states (\(c_t\) and \(h_t\)), GRUs use only the hidden state \(h_t\). Two gates are used to control information flow:

  • Update gate \(z_t\): Determines how much of the previous hidden state should be retained.
  • Reset gate \(r_t\): Controls how much of the past information to forget before computing the candidate activation.

This structure balances simplicity with effectiveness, allowing the GRU to selectively memorize or discard information as needed.

GRU Equations

At each time step \(t\), the GRU performs the following computations:

\[ \begin{align*} z_t &= \sigma(W_z [h_{t-1}, x_t] + b_z) \\\\ r_t &= \sigma(W_r [h_{t-1}, x_t] + b_r) \\\\ \tilde{h}_t &= \tanh(W_h [r_t \cdot h_{t-1}, x_t] + b_h) \\\\ h_t &= (1 - z_t) \cdot h_{t-1} + z_t \cdot \tilde{h}_t \end{align*} \]
  • \(z_t\) controls the blend between the old and new information.
  • \(r_t\) allows the model to reset memory when appropriate.
  • \(\tilde{h}_t\) is the candidate activation for the new hidden state.
  • \(h_t\) is the final hidden state output for the current time step.

GRUs directly update the hidden state \(h_t\) using a weighted sum of the previous state and the new candidate. This allows them to efficiently retain or overwrite past information.

Functional Summary

  • Memory merging: GRUs combine short-term and long-term memory into a single vector.
  • Simplified flow: Fewer gates reduce the number of parameters and computational overhead.
  • Training speed: GRUs often converge faster than LSTMs, especially on smaller or less complex datasets.

In practice, GRUs tend to perform comparably to LSTMs in many tasks, but with reduced training time and resource usage.

Now that we've examined the internal mechanisms of both LSTMs and GRUs, we can directly compare them across structural and functional dimensions. Understanding their differences will help you choose the right architecture for different types of sequence modeling tasks.

LSTM vs GRU: Structural and Functional Comparison

Now that we've explored both LSTM and GRU architectures, it's important to compare them side by side to understand their trade-offs. Both models were designed to preserve gradient flow and capture long-range dependencies, but they do so using different structural strategies.

Key Differences

Memory Structure

  • LSTM maintains two states: the hidden state (\(h_t\)) and the cell state (\(c_t\)).
  • GRU combines these into a single hidden state (\(h_t\)), simplifying the architecture.

Gating Mechanism

  • LSTM uses three gates: input, forget, and output.
  • GRU uses two: update and reset.

Parameter Count

  • GRUs generally have fewer parameters than LSTMs, making them faster to train and more memory-efficient.

Expressiveness

  • LSTMs offer more control and flexibility due to the separation of memory and output.
  • GRUs, while simpler, often perform just as well in practice—especially on tasks where model capacity is not a bottleneck.

Practical Comparison Table

Aspect LSTM GRU
Number of Gates 3 (input, forget, output) 2 (update, reset)

Choosing Between LSTM and GRU

There’s no universal rule for when to use LSTM or GRU. Here are general guidelines:

  • Use LSTM if:
    • Your data has complex long-range dependencies.
    • You can afford longer training times for potentially better performance.
    • You need explicit memory control or want to experiment with gating behavior.
  • Use GRU if:
    • You want faster training with fewer parameters.
    • You’re working with smaller datasets or limited compute.
    • You need a compact model for real-time or edge applications.

In practice, both LSTMs and GRUs are strong choices—selecting one depends on the problem, data scale, and resource constraints.

Practical Example: Comparing LSTM and GRU in Code

To illustrate how LSTMs and GRUs handle sequence memory, consider the following example. We generate binary sequences where the first token determines the class label. The model must retain that early token throughout the entire sequence to make the correct prediction—ideal for testing long-term memory in recurrent units.

Task Setup

import torch
import torch.nn as nn
import numpy as np

# Generate sequences of 0s and 1s; label is the first token
def generate_data(num_samples=10000, seq_len=10):
    X = np.random.randint(0, 2, (num_samples, seq_len))
    y = X[:, 0]  # Label = first token
    return torch.tensor(X, dtype=torch.long), torch.tensor(y, dtype=torch.float32)

X, y = generate_data()

LSTM-Based Classifier

class LSTMClassifier(nn.Module):
    def __init__(self, input_dim, hidden_dim):
        super().__init__()
        self.embedding = nn.Embedding(input_dim, 8)
        self.lstm = nn.LSTM(input_size=8, hidden_size=hidden_dim, batch_first=True)
        self.fc = nn.Linear(hidden_dim, 1)

    def forward(self, x):
        x = self.embedding(x)
        _, (h_n, _) = self.lstm(x)
        return torch.sigmoid(self.fc(h_n[-1]))

GRU-Based Classifier

class GRUClassifier(nn.Module):
    def __init__(self, input_dim, hidden_dim):
        super().__init__()
        self.embedding = nn.Embedding(input_dim, 8)
        self.gru = nn.GRU(input_size=8, hidden_size=hidden_dim, batch_first=True)
        self.fc = nn.Linear(hidden_dim, 1)

    def forward(self, x):
        x = self.embedding(x)
        _, h_n = self.gru(x)
        return torch.sigmoid(self.fc(h_n[-1]))

Training Loop

def train(model, X, y, epochs=5):
    optimizer = torch.optim.Adam(model.parameters(), lr=0.01)
    loss_fn = nn.BCELoss()

    for epoch in range(epochs):
        model.train()
        optimizer.zero_grad()
        y_pred = model(X).squeeze()
        loss = loss_fn(y_pred, y)
        loss.backward()
        optimizer.step()
        print(f"Epoch {epoch+1}, Loss: {loss.item():.4f}")

Run Both Models

lstm_model = LSTMClassifier(input_dim=2, hidden_dim=16)
train(lstm_model, X, y)

gru_model = GRUClassifier(input_dim=2, hidden_dim=16)
train(gru_model, X, y)

Interpretation

Both models are trained on the same task. The LSTM may be slightly slower but preserves memory explicitly through a cell state. The GRU, while faster and simpler, often reaches similar accuracy with fewer parameters.

This example shows how model choice affects training speed and complexity, especially for tasks that require sequence memory.

Conclusion

Vanilla RNNs struggle with long-term dependencies due to vanishing gradients. LSTMs and GRUs introduce memory and gating mechanisms that solve this problem. LSTMs use separate cell and hidden states with three gates, while GRUs simplify the model by merging these with only two gates.
