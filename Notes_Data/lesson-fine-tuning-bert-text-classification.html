Overview of BERT for Classification

This lesson focuses on fine-tuning BERT for text classification tasks such as sentiment analysis, spam detection, or topic identification. To understand how BERT can be adapted to such tasks, we first examine how it is pre-trained. BERT (Bidirectional Encoder Representations from Transformers) is a general-purpose language understanding model, pre-trained on large volumes of unannotated text using two unsupervised objectives:

  • Masked Language Modeling (MLM): Random tokens in the input are replaced with a [MASK] token, and the model learns to predict the original tokens from context. This enables BERT to capture bidirectional contextual information.
  • Next Sentence Prediction (NSP): BERT is trained to determine whether one sentence logically follows another. This enhances its ability to model inter-sentence relationships, which are crucial for many NLP tasks.

These objectives allow BERT to learn deep, transferable language representations, which serve as the foundation for downstream applications. In classification tasks, BERT is typically fine-tuned by:

  • Adding a classification layer (e.g., a fully connected dense layer) on top of the [CLS] token representation.
  • Training the entire model on labeled examples for the specific classification objective.

This fine-tuning process allows BERT to adapt its general language understanding to the specific decision boundaries required for the classification task at hand.

BERT architecture for classification

Architecture Adaptation for Classification

Having explored how BERT is pre-trained using Masked Language Modeling (MLM) and Next Sentence Prediction (NSP), we now examine how its architecture is adapted for downstream tasks, specifically, text classification. This is a critical step in fine-tuning BERT, enabling it to apply its general language understanding to task-specific objectives.

From Pretraining to Downstream Use

BERT is designed to output a contextual embedding for each token in the input sequence. The [CLS] token, which is prepended to every input during pretraining, is designated to capture an aggregate representation of the entire sequence. This makes it a natural choice for classification tasks, where a fixed-size summary of the input is needed.

Modifying BERT for Classification

To transform BERT into a classifier, the architecture is modified as follows:

  1. Extract the [CLS] token's final hidden state from the last encoder layer. This vector serves as the representation of the entire input.
  2. Apply dropout to this vector for regularization, reducing the risk of overfitting during fine-tuning.
  3. Pass the result through a fully connected (dense) layer, typically followed by a softmax activation for multi-class classification or a sigmoid activation for binary classification.

Why This Design Works

This adaptation preserves BERT’s deep contextual understanding from pretraining while enabling it to learn new classification boundaries tailored to the target dataset. Since only a small number of parameters (in the classifier head) are added, fine-tuning remains efficient and data-friendly even with limited labeled data.

Fine-Tuning BERT on a Classification Dataset with Hugging Face

With the architectural adaptation in place, we now shift to practical implementation. In this section, we'll fine-tune a pre-trained BERT model for binary classification using the Hugging Face Transformers library and the "shawhin/phishing-site-classification" dataset.

Loading and Applying the Tokenizer

We now load a pre-trained BERT tokenizer and model with a classification head suitable for binary classification:

# Define pre-trained model name
model_path = "google-bert/bert-base-uncased"

# Load tokenizer
tokenizer = AutoTokenizer.from_pretrained(model_path)

# Load pre-trained model with classification head
id2label = {0: "Safe", 1: "Not Safe"}
label2id = {"Safe": 0, "Not Safe": 1}

model = AutoModelForSequenceClassification.from_pretrained(
    model_path,
    num_labels=2,
    id2label=id2label,
    label2id=label2id
)

Explanation:

  • AutoModelForSequenceClassification loads BERT with a classification head and softmax layer.
  • num_labels=2 specifies a binary classification task.

Freezing the Base Model (Optional but Recommended)

Fine-tuning all of BERT’s parameters is resource-intensive. We can instead freeze the base model and train only the final classification layers:

# Freeze all base model parameters
for name, param in model.base_model.named_parameters():
    param.requires_grad = False

# Optionally unfreeze specific layers (e.g., pooler)
for name, param in model.base_model.named_parameters():
    if "pooler" in name:
        param.requires_grad = True

This strategy significantly reduces training time and overfitting risks when working with small or medium-sized datasets.

Formatting the Dataset and Launching Fine-Tuning

After loading and preparing the model and tokenizer, the next step is to preprocess the dataset, define the evaluation metrics, configure the training process, and launch fine-tuning. This pipeline ensures the model is trained efficiently while tracking performance using standard metrics.

Preprocessing and Tokenization

We begin by tokenizing the raw text data using the pre-trained BERT tokenizer. This involves truncating longer sequences and preparing them for batch processing:

def preprocess_function(examples):
    return tokenizer(examples["text"], truncation=True)

tokenized_data = dataset_dict.map(preprocess_function, batched=True)

To ensure all input sequences in a batch are of uniform length, we use a data collator:

data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

Defining the Evaluation Metrics

To evaluate model performance, we use two metrics:

  • Accuracy: Measures the proportion of correct predictions.
  • AUC (Area Under the Curve): Captures the quality of probabilistic predictions for binary classification.

We define a helper function that computes both metrics from model outputs:

accuracy = evaluate.load("accuracy")
auc_score = evaluate.load("roc_auc")

def compute_metrics(eval_pred):
    predictions, labels = eval_pred
    probabilities = np.exp(predictions) / np.exp(predictions).sum(-1, keepdims=True)
    positive_class_probs = probabilities[:, 1]

    auc = np.round(auc_score.compute(prediction_scores=positive_class_probs, references=labels)['roc_auc'], 3)
    predicted_classes = np.argmax(predictions, axis=1)
    acc = np.round(accuracy.compute(predictions=predicted_classes, references=labels)['accuracy'], 3)

    return {"Accuracy": acc, "AUC": auc}

This function ensures our model is assessed both on classification accuracy and how confidently it makes decisions.

Configuring Training with TrainingArguments

We define the core training configuration, including batch size, learning rate, number of epochs, and evaluation strategy:

lr = 2e-4
batch_size = 16
num_epochs = 4

training_args = TrainingArguments(
    output_dir="bert-phishing-classifier_teacher",
    learning_rate=lr,
    per_device_train_batch_size=batch_size,
    per_device_eval_batch_size=batch_size,
    num_train_epochs=num_epochs,
    logging_strategy="epoch",
    eval_strategy="epoch",
    save_strategy="epoch",
    load_best_model_at_end=True,
    report_to="none",
)

These settings help manage training time, validation checkpoints, and model checkpointing.

Launching Fine-Tuning with Trainer

We now wrap everything into the Hugging Face Trainer class and begin training:

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_data["train"],
    eval_dataset=tokenized_data["test"],
    tokenizer=tokenizer,
    data_collator=data_collator,
    compute_metrics=compute_metrics,
)

trainer.train()

This automatically handles forward and backward passes, loss computation, and metric logging each epoch.

Explanation:

  • train_dataset and eval_dataset: Our processed training and test data.
  • tokenizer: Passed so that dynamic padding remains consistent.
  • compute_metrics: Used to calculate accuracy after each evaluation step.

Final Evaluation

After training, we evaluate the model on the validation set:

predictions = trainer.predict(tokenized_data["validation"])
logits = predictions.predictions
labels = predictions.label_ids

metrics = compute_metrics((logits, labels))
print(metrics)

Expected Output:

{'Accuracy': 0.88, 'AUC': 0.936}
