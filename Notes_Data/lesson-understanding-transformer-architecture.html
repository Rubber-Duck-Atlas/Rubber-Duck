Lesson: Understanding Transformer Architecture

Introduction

So far, we have worked with RNN-based Sequence-to-Sequence (Seq2Seq) models with and without attention. While attention helped overcome the fixed-length bottleneck, RNNs remain sequential in nature, making training and inference slow and difficult to parallelize, especially with long sequences. To address these challenges, researchers at Google introduced the Transformer architecture in 2017. Unlike RNNs, Transformers do not use recurrence at all. Instead, they rely entirely on self-attention mechanisms, allowing for parallel computation, long-range context modeling, and scalable training. In this lesson, we will explore how the Transformer architecture is structured, how it solves the limitations of RNNs, and how its components, self-attention, positional encoding, and feed-forward layers work together to process text efficiently and effectively.

Learning Outcomes

By the end of this lesson, you will be able to:

  1. Explain how the Transformer architecture eliminates the limitations of RNN-based models.
  2. Describe the key components of the Transformer, including self-attention, positional encoding, and feed-forward layers.
  3. Compare RNN-based sequence models and Transformer models in terms of design, performance, and scalability.

Limitations of RNNs Revisited

Before we dive into the Transformer architecture, it’s important to revisit the foundational challenges that motivated its development. Recurrent Neural Networks (RNNs) and Long Short-Term Memory networks (LSTMs) were once the dominant architectures for sequential data. While they brought major advances in tasks like machine translation, they also exposed core limitations, especially as models scaled to longer sequences and more complex tasks.

RNN-based architectures process input sequences token-by-token, passing hidden states from one time step to the next. This design introduces several constraints:

  • Long-Range Dependency DegradationAs the input sequence grows, early tokens struggle to influence distant outputs. Even with LSTMs, which mitigate vanishing gradients, the signal weakens over time.
  • Sequential Computation BottleneckRNNs cannot compute all time steps in parallel. Each token’s output depends on the one before it, preventing hardware-level parallelism during both training and inference.
  • Weak Global Context ModelingSince each output is primarily driven by local context (the current token and recent states), RNNs struggle with tasks requiring an understanding of the entire sequence, such as document-level translation or summarization.

Transformer Solution

Transformers address all of these limitations through a non-recurrent, fully attention-based architecture. By replacing recurrence with self-attention, Transformers:

  • Capture global dependencies regardless of sequence length.
  • Allow parallel computation across all tokens.
  • Dynamically compute contextual relationships between all pairs of tokens.

This paradigm shift enables faster training, better scalability, and higher performance across nearly all sequence modeling tasks in NLP and beyond.

Parallelism in Transformers

One of the most transformative advantages of the Transformer architecture over RNNs lies in its ability to process sequences in parallel. Traditional RNNs rely on sequential computation, where each token's processing depends on the completion of the previous one. This inherently limits training speed and makes long-sequence modeling inefficient. Transformers overcome this bottleneck by eliminating recurrence entirely, enabling parallel computation across all tokens in both the input and output sequences.

How Transformers Achieve Parallelism

Transformers rely on two key innovations to support non-sequential processing:

  • Self-Attention Mechanism: Each token in the input sequence can attend to all other tokens simultaneously. This means the model does not need to wait for previous tokens to be processed before computing the current token's representation.
  • Positional Encoding: Because the model has no built-in notion of sequence order (unlike RNNs), positional encodings are added to input embeddings. These encodings inject information about the relative or absolute position of each token, allowing the model to preserve sequential structure without recurrence.

Benefits of Parallelism

  • Significant SpeedupAll tokens are processed in parallel, enabling faster training on modern hardware (e.g., GPUs and TPUs) and better scalability to long sequences.
  • Improved Long-Range Dependency ModelingSince every token can directly access all others in a single layer, the model can capture global context more effectively than architectures limited by stepwise recurrence.

Transformers shift the paradigm from sequential to parallel processing. By leveraging self-attention and positional encodings, they not only achieve faster computation but also unlock the ability to model complex, long-range relationships in a fundamentally different and more efficient way.

Component 1: Self-Attention

Now that we've seen how Transformers enable parallelism through the removal of recurrence, we turn to the core mechanism that makes this possible: self-attention. This mechanism allows the model to capture dependencies between all tokens in a sequence regardless of their distance from one another while preserving the flexibility to compute representations in parallel.

Self-attention is a mechanism that enables each token in the input sequence to compute a weighted representation of all other tokens, including itself. These weights are learned dynamically, allowing the model to "attend" to the most relevant parts of the sequence when encoding a particular token. This is especially powerful for tasks involving context, coreference, or long-distance relationships.

Query, Key, and Value

To compute attention, each input token is projected into three learned vectors:

  • Query (Q): Represents what the current token is looking for.
  • Key (K): Represents what each token offers to other tokens.
  • Value (V): Contains the actual information passed to the output based on attention scores.

These vectors are learned through linear transformations applied to the input embeddings.

Attention Computation

The attention score between a query and a set of keys is calculated using the scaled dot-product formula. The attention score between tokens \(i\) and \(j\) is computed as:

\[ \text{Attention}(Q, K, V) = \text{softmax} \left( \frac{QK^\top}{\sqrt{d_k}} \right) V \]

Where:

  • \(Q \in \mathbb{R}^{n \times d_k}\) is the matrix of queries.
  • \(K \in \mathbb{R}^{n \times d_k}\) is the matrix of keys.
  • \(V \in \mathbb{R}^{n \times d_v}\) is the matrix of values.
  • \(d_k\) is the dimension of the key vectors, used to scale the dot products for numerical stability.

The softmax operation ensures that attention weights are positive and sum to 1, forming a probability distribution over all tokens. This allows modeling of both local and global dependencies.

Benefits of Self-Attention

Self-attention enables the model to:

  • Capture local and global dependencies in a single layer.
  • Weight different parts of the input based on their relevance to the current token.
  • Model token relationships bidirectionally and simultaneously.

Component 2: Multi-Head Attention (MH-ATT)

While a single self-attention mechanism allows each token to attend to others in the sequence, it may not be sufficient to capture the full range of relationships—especially in complex sentences with multiple linguistic cues. To address this, Transformers use multiple self-attention mechanisms in parallel, allowing the model to learn diverse types of dependencies simultaneously. This extension is known as Multi-Head Attention.

Rather than computing a single set of attention weights, the Transformer splits the input into multiple attention heads. Each head independently performs self-attention with its own set of learned projections. This allows each head to specialize:

  • Some heads may capture syntactic structures (e.g., subject–verb agreement).
  • Others may focus on semantic relationships (e.g., co-reference or synonymy).
  • Some may emphasize positional or contextual patterns.

Formal Definition

Each attention head is computed using distinct projections of \(Q\), \(K\), and \(V\):

\[ \text{head}_i = \text{Attention}(QW^Q_i, KW^K_i, VW^V_i) \]

The outputs from all heads are then concatenated and projected through a final linear layer:

\[ \text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, ..., \text{head}_h) W^O \]

Where:

  • \(W^Q_i\), \(W^K_i\), \(W^V_i\) are learned weight matrices for the \(i\)‑th head.
  • \(W^O\) is the output projection matrix applied after concatenation.

Benefits of Multi-Head Attention

  • Richer Representations: Each head learns a distinct attention pattern, capturing different aspects of language structure.
  • Parallel Processing: All heads compute in parallel, maintaining the transformer's efficiency.
  • Enhanced Generalization: The model becomes more robust to variation in syntax, phrasing, and context.

Component 3: Positional Encoding

While multi-head self-attention enables Transformers to learn complex dependencies across tokens, it has one critical limitation: it is position-agnostic. Since all tokens are processed simultaneously, the model lacks any built-in understanding of sequence order, a crucial element in natural language.To address this, Transformers introduce positional encoding, a method for injecting information about token positions directly into the model’s input representations.

Unlike RNNs or CNNs, Transformers do not process input sequentially or locally. Without additional information, the model would treat "cat sat on mat" and "mat sat on cat" identically, even though their meanings differ entirely due to word order. To solve this, a positional encoding vector is added to each input embedding. These encodings are deterministic, fixed-length vectors based on the position of each token in the sequence.

Mathematical Formulation

The positional encoding for each position \(pos\) and each embedding dimension \(i\) is defined as:

\[ PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right), \quad PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right) \]

Where:

  • \(pos\) is the position index (starting from 0),
  • \(i\) is the dimension index,
  • \(d_{\text{model}}\) is the total dimension of the model's embeddings.

These sinusoidal encodings produce values that vary smoothly across positions and dimensions, allowing the model to infer relative and absolute positions through attention.

Key Properties

  • Fixed and Non-Trainable: Unlike embeddings, these encodings are not learned—they are computed using sine and cosine functions.
  • Generalizable: The periodic nature of sinusoids allows the model to extrapolate to longer sequences than those seen during training.
  • Additive: Positional encodings are added directly to the input token embeddings before they enter the first attention layer.

Positional encoding gives the Transformer a sense of order, enabling it to interpret the sequence of words despite its fully parallel architecture. Combined with self-attention and multi-head attention, this forms the foundation for the model’s ability to understand and generate structured text.

Component 4: Feed-Forward Network (FFN)

After the model encodes relationships between tokens through self-attention and integrates position information via positional encoding, each token representation is passed through a fully connected feed-forward network. This component allows the model to perform non-linear transformations independently at each position, enabling richer token-level representations.

Within each Transformer layer, a position-wise feed-forward network (FFN) is applied to the output of the multi-head attention mechanism. Unlike traditional neural networks where layers operate on the entire input collectively, here the same FFN is applied identically and independently to each token embedding in the sequence.

Mathematical Definition

The feed-forward network consists of two linear transformations with a ReLU activation in between:

\[ \text{FFN}(x) = \max(0, xW_1 + b_1)W_2 + b_2 \]

Where:

  • \(x\) is the input vector at a given position,
  • \(W_1\) and \(W_2\) are learned weight matrices,
  • \(b_1\) and \(b_2\) are learned bias vectors,
  • \(\max(0, \cdot)\) denotes the ReLU activation function.

Each \(x\) is transformed individually and identically, making the operation position-wise but not sequence-dependent.

Purpose and Benefits

  • Increased Representation Capacity: The FFN adds depth and non-linearity, enabling the model to learn more complex transformations beyond what attention alone can capture.
  • Token-Level Processing: Since it's applied per position, the FFN enhances each token's representation after contextual relationships have been captured through attention.
  • Modular Simplicity: The FFN is simple and highly parallelizable, contributing to the Transformer's computational efficiency.

The feed-forward network provides an essential non-linear transformation stage within each Transformer block. By applying it individually to each token, the model boosts its ability to learn nuanced semantic features without compromising its parallel structure.

Encoder and Decoder Stacks

After understanding the core components of the Transformer, self-attention, multi-head attention, positional encoding, and feed-forward networks, we now examine how these elements are organized into full model architectures. The Transformer is composed of two primary modules: the encoder stack and the decoder stack, each built by repeating the core components in structured layers.

Transformer Architecture Overview

The Transformer consists of:

Encoder Stack: A sequence of \(N\) identical layers, where each layer contains:

  1. Multi-head self-attention
  2. Position-wise feed-forward network
  3. Residual connections and layer normalization (applied after each sub-layer)

Decoder Stack: Also composed of \(N\) identical layers, but with three sub-layers:

  1. Masked multi-head self-attention: Ensures the decoder can only attend to earlier positions in the output sequence (important for autoregressive generation).
  2. Encoder–decoder attention: Enables the decoder to attend to the encoder’s outputs, allowing alignment between input and output sequences.
  3. Feed-forward network, followed again by residual connections and normalization.

This enables auto-regressive generation in tasks like translation, where the decoder only sees past tokens during training.

Auto-Regressive Generation

The decoder is designed for auto-regressive tasks like machine translation or text generation.

During training:

  • The decoder can only attend to past tokens (due to masking).
  • This prevents it from "cheating" by looking at future words.

During inference:

  • The model generates one token at a time, feeding the output back into the decoder for the next step.

The Transformer’s encoder–decoder structure supports both input encoding and autoregressive output generation. This modular stacking of attention and feed-forward layers with masking and cross-attention in the decoder enables powerful sequence modeling across many tasks.

Comparing RNNs and Transformers

Having examined the structure and components of the Transformer, it’s instructive to compare it with traditional sequence models—particularly Recurrent Neural Networks (RNNs) and their variants like LSTMs and GRUs. While RNNs dominated sequence learning tasks for many years, Transformers represent a fundamental shift in architecture and learning capabilities.

Feature RNN-Based Models Transformers
Architecture Sequential (time-step by time-step) Parallel across the full sequence
Context Propagation Through hidden states Through attention over all positions
Sequence Processing Left-to-right (or bidirectional with effort) All-at-once (no recurrence)
Training Efficiency Slower (no parallelism) Faster due to full parallelism
Long-Range Dependency Capture Limited (vanishing gradients) Excellent (global attention)
Positional Awareness Implicit in sequence Requires explicit positional encoding
Scalability Poor for long sequences Highly scalable to long sequences
Memory Usage Low High (especially with long inputs)
Hardware Utilization Less efficient (sequential) Highly optimized for GPUs/TPUs

Summary

  • RNNs process input tokens sequentially, carrying information via a hidden state from one step to the next. While this allows them to model temporal sequences, it also makes them slow and difficult to parallelize, and limits their ability to capture long-range dependencies.
  • Transformers, in contrast, process entire sequences in parallel using self-attention. Each token can attend to all others, allowing for better context modeling and faster training, especially on modern hardware.
