Lesson: Performance & Best Practices

By the end of this lesson, you’ll have a solid understanding of how to organize and optimize your application’s state effectively.

Preventing Excessive Re-Renders with Selective State Usage

One of the most common performance challenges in state management is excessive re-renders, where components update unnecessarily even when unrelated parts of the state change. This issue can slow down your application and make it feel sluggish. To address this, Zustand provides a solution by allowing components to subscribe only to specific slices of the state rather than the entire store. This approach ensures that a component re-renders only when the part of the state it depends on changes, minimizing unnecessary updates.

Here’s how it works: Zustand’s useStore hook lets you extract only the state properties your component needs. By doing so, the component becomes more efficient because it doesn’t react to unrelated state changes. For example:

import create from 'zustand';

// Create a Zustand store
const useStore = create((set) => ({
  count: 0,
  title: 'My App',
  increment: () => set((state) => ({ count: state.count + 1 })),
}));

// Component A: Only subscribes to `count`
function Counter() {
  const count = useStore((state) => state.count);
  return <h1>Count: {count}</h1>;
}

// Component B: Only subscribes to `title`
function Title() {
  const title = useStore((state) => state.title);
  return <h2>{title}</h2>;
}

In this example:

  • The Counter component listens only to changes in the count property.
  • The Title component listens only to changes in the title property.
  • When count is updated, only the Counter component re-renders, leaving the Title component unaffected.

This selective state subscription reduces computational overhead and improves performance by ensuring that components respond only to relevant state changes.

React-Specific Optimizations: useMemo and useCallback

When building React applications, optimizing performance is crucial for delivering a smooth and responsive user experience. Two powerful tools for achieving this are the useMemo and useCallback hooks. While both aim to enhance performance, they serve different purposes and are best suited for specific scenarios.

Optimizing Expensive Calculations with useMemo

The useMemo hook helps optimize performance by memoizing (or caching) the result of a function. This means that expensive computations—like complex calculations or data transformations—are performed only when necessary, rather than on every render. By storing the computed value, React avoids recalculating it unless its dependencies change.

Here’s an example to illustrate how useMemo works:

import { useMemo } from "react";

function ExpensiveCalculationComponent({ num }) {
  const squaredNumber = useMemo(() => {
    console.log("Computing square...");
    return num * num;
  }, [num]);

  return <p>Squared Number: {squaredNumber}</p>;
}

In this example:

  • The message "Computing square..." appears in the console only when the num prop changes.
  • If num remains the same across renders, the cached result is reused, preventing unnecessary recalculations.

By using useMemo, you can ensure that computationally intensive tasks don’t bog down your application, especially when dealing with large datasets or frequent updates.

Stabilizing Function References with useCallback

While useMemo focuses on caching computed values, the useCallback hook is used to memoize function references. This ensures that the same function instance is reused across renders unless its dependencies change. This is particularly useful when passing functions as props to child components, as it prevents unnecessary re-renders caused by new function instances being created on every render.

Here’s an example to demonstrate useCallback:

import { useCallback, useState } from "react";

function Button({ handleClick }) {
  return <button onClick={handleClick}>Click Me</button>;
}

function ParentComponent() {
  const [count, setCount] = useState(0);

  const increment = useCallback(() => {
    setCount((prev) => prev + 1);
  }, []);

  return (
    <div>
      <p>Count: {count}</p>
      <Button handleClick={increment} />
    </div>
  );
}

In this example:

  • The increment function is memoized using useCallback.
  • Since the function reference remains stable between renders, the Button component won’t re-render unnecessarily.

By stabilizing function references, useCallback helps maintain performance, especially in larger applications with deeply nested components.

Splitting Large Stores into Slices for Better Organization

As applications grow in complexity, managing a single large global state can become overwhelming. To address this, modern state management libraries like Redux Toolkit allow you to break down the global state into smaller, modular pieces called slices. Each slice represents a specific part of the application’s state and encapsulates its own logic for managing that state. This approach not only improves code organization but also makes it easier to maintain and scale your application.

Why Splitting Stores into Slices Matters

Imagine building an e-commerce application with features like user authentication, a shopping cart, and a product catalog. If all the state for these features is stored in one place, it becomes difficult to locate and manage specific parts of the state. For example, debugging issues related to the shopping cart might require sifting through unrelated data about products or user sessions. This lack of structure can slow down development and make the code harder to understand.

By dividing the state into slices—such as auth for user authentication, cart for shopping cart data, and products for the product catalog—you create a clear separation of concerns. Each slice focuses on a specific domain, making it easier to locate, update, and debug related logic. Additionally, this modular approach allows teams to work on different features independently without interfering with each other’s code.

How to Split a Store into Slices

Let’s walk through the process of splitting a store into slices using Redux Toolkit, which simplifies state management in React applications. We’ll use an e-commerce application as an example, with three main features: user authentication (auth), shopping cart (cart), and product catalog (products).

Step 1: Install Redux Toolkit

Before we begin, ensure you have Redux Toolkit installed in your project. You can install it using npm or yarn:

npm install @reduxjs/toolkit react-redux

This toolkit includes everything you need to manage state efficiently, including utilities for creating slices and combining them into a single store.

Step 2: Create Feature-Specific Slices

Each slice defines its initial state, reducers (functions that handle state updates), and actions (functions that trigger state changes). Let’s create slices for auth, cart, and products.

Auth Slice (authSlice.js)

The auth slice manages user authentication-related state, such as whether the user is logged in and their profile information.

import { createSlice } from '@reduxjs/toolkit';

const authSlice = createSlice({
  name: 'auth', // Name of the slice
  initialState: {
    isLoggedIn: false,
    user: null,
  },
  reducers: {
    login(state, action) {
      state.isLoggedIn = true;
      state.user = action.payload; // Update state with user data
    },
    logout(state) {
      state.isLoggedIn = false;
      state.user = null; // Clear user data
    },
  },
});

export const { login, logout } = authSlice.actions; // Export actions for use in components
export default authSlice.reducer; // Export reducer to combine with other slices

Here, the login and logout actions allow us to update the authentication state. These actions are automatically generated by createSlice, eliminating the need for boilerplate code.

Cart Slice (cartSlice.js)

The cart slice handles the shopping cart, including items and their quantities. It ensures that adding or removing items updates the total cost correctly.

import { createSlice } from '@reduxjs/toolkit';

const cartSlice = createSlice({
  name: 'cart',
  initialState: {
    items: [],
    total: 0,
  },
  reducers: {
    addItem(state, action) {
      const item = action.payload;
      const existingItem = state.items.find((i) => i.id === item.id);
      if (existingItem) {
        existingItem.quantity += 1; // Increment quantity if item already exists
      } else {
        state.items.push({ ...item, quantity: 1 }); // Add new item with quantity 1
      }
      state.total += item.price; // Update total cost
    },
    removeItem(state, action) {
      const itemId = action.payload;
      const item = state.items.find((i) => i.id === itemId);
      if (item) {
        state.total -= item.price * item.quantity; // Subtract item’s total cost
        state.items = state.items.filter((i) => i.id !== itemId); // Remove item
      }
    },
  },
});

export const { addItem, removeItem } = cartSlice.actions;
export default cartSlice.reducer;

In this slice, the addItem and removeItem actions ensure that the cart state is updated correctly whenever a user adds or removes an item. The logic for calculating the total cost is handled within the slice, keeping the component code clean and focused on rendering.

Products Slice (productsSlice.js)

The products slice manages the product catalog, including fetching products from an API. Since fetching data involves asynchronous operations, we’ll use createAsyncThunk to handle this.

import { createSlice, createAsyncThunk } from '@reduxjs/toolkit';

// Async thunk to fetch products
export const fetchProducts = createAsyncThunk('products/fetchProducts', async () => {
  const response = await fetch('/api/products');
  const data = await response.json();
  return data; // Return fetched products
});

const productsSlice = createSlice({
  name: 'products',
  initialState: {
    products: [],
    loading: false,
    error: null,
  },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchProducts.pending, (state) => {
        state.loading = true; // Set loading to true when fetching starts
      })
      .addCase(fetchProducts.fulfilled, (state, action) => {
        state.loading = false; // Set loading to false when fetching succeeds
        state.products = action.payload; // Update state with fetched products
      })
      .addCase(fetchProducts.rejected, (state, action) => {
        state.loading = false; // Set loading to false when fetching fails
        state.error = action.error.message; // Store error message
      });
  },
});

export default productsSlice.reducer;

Here, fetchProducts is an asynchronous action that fetches product data from an API. The extraReducers field handles the different stages of the asynchronous operation (pending, fulfilled, and rejected), updating the state accordingly.

Step 3: Combine Slices into a Single Store

Once the slices are created, you need to combine them into a single Redux store. This is done using configureStore, which simplifies the process of setting up the store.

import { configureStore } from '@reduxjs/toolkit';
import authReducer from './authSlice';
import cartReducer from './cartSlice';
import productsReducer from './productsSlice';

const store = configureStore({
  reducer: {
    auth: authReducer,
    cart: cartReducer,
    products: productsReducer,
  },
});

export default store;

The configureStore function automatically sets up middleware (like support for asynchronous actions) and enables Redux DevTools for debugging.

Step 4: Provide the Store to Your Application

To make the store available throughout your application, wrap your app with the Provider component from react-redux.

import React from 'react';
import ReactDOM from 'react-dom';
import { Provider } from 'react-redux';
import store from './store';
import App from './App';

ReactDOM.render(
  <Provider store={store}>
    <App />
  </Provider>,
  document.getElementById('root')
);

With this setup, any component in your application can access the global state or dispatch actions to update it.

Accessing State and Dispatching Actions

To interact with the state in your components, you can use the useSelector and useDispatch hooks from react-redux. These hooks allow you to retrieve specific parts of the state and trigger actions.

Example: Displaying Cart Items
import React from 'react';
import { useSelector, useDispatch } from 'react-redux';
import { addItem, removeItem } from './cartSlice';

function Cart() {
  const cart = useSelector((state) => state.cart); // Access cart state
  const dispatch = useDispatch();

  return (
    <div>
      <h2>Cart</h2>
      <ul>
        {cart.items.map((item) => (
          <li key={item.id}>
            {item.name} - ${item.price} x {item.quantity}
            <button onClick={() => dispatch(removeItem(item.id))}>Remove</button>
          </li>
        ))}
      </ul>
      <p>Total: ${cart.total}</p>
    </div>
  );
}

export default Cart;

In this example:

  • The useSelector hook retrieves the cart state.
  • The useDispatch hook allows us to call the removeItem action when a user clicks the "Remove" button.

Middleware: Logging and Persistence in Zustand

Zustand, a lightweight state management library, supports middleware, which extends your store’s functionality with features like logging and persistence. Middleware acts as an intermediary layer that intercepts state updates, allowing you to add custom behavior such as tracking changes or saving data to storage.

Logging Middleware: Track State Changes for Debugging

During development, tracking how your application’s state changes over time can be invaluable for debugging. Logging middleware helps by recording the state before and after each update, giving you insights into what’s happening under the hood.

Here’s how you can implement logging middleware in Zustand:

import create from 'zustand';

// Define a logging middleware function
const log = (config) => (set, get, api) =>
  config(
    (...args) => {
      console.log('State before:', get()); // Log the current state
      set(...args); // Apply the state update
      console.log('State after:', get()); // Log the updated state
    },
    get,
    api
  );

// Create a store with logging middleware
const useStore = create(
  log((set) => ({
    count: 0,
    increment: () => set((state) => ({ count: state.count + 1 })),
  }))
);

In this example:

  • The log function wraps the store’s set method to log the state before and after each update.
  • When you call the increment function, the console displays the state before and after the change, helping you understand how the state evolves over time.

Persistence Middleware: Save State Across Page Reloads

Another powerful feature of middleware is persistence, which ensures that your application’s state survives page reloads. Without persistence, any state stored in memory is lost when the user refreshes the page. By saving the state to localStorage or sessionStorage, you can provide a seamless experience where users don’t lose their progress or preferences.

Here’s how you can implement persistence middleware in Zustand:

import create from 'zustand';
import { persist } from 'zustand/middleware';

// Create a store with persistence middleware
const useStore = create(
  persist(
    (set) => ({
      count: 0,
      increment: () => set((state) => ({ count: state.count + 1 })),
    }),
    {
      name: 'my-store', // Key used to identify the data in localStorage
    }
  )
);

In this example:

  • The persist middleware saves the store’s state to localStorage under the key 'my-store'.
  • When the user reloads the page, the state is automatically restored from localStorage, ensuring continuity.

For instance, if the count value was incremented to 5 before the page reload, it will remain 5 after the reload, thanks to persistence. You can also customize the storage mechanism by specifying options like storage: sessionStorage if you prefer session-based persistence.

Combining Middleware for Enhanced Functionality

Zustand allows you to combine multiple middleware functions to achieve more advanced functionality. For example, you can use both logging and persistence together to track state changes while ensuring they persist across sessions.

import create from 'zustand';
import { devtools, persist } from 'zustand/middleware';

// Combine logging and persistence middleware
const useStore = create(
  persist(
    log((set) => ({
      count: 0,
      increment: () => set((state) => ({ count: state.count + 1 })),
    })),
    {
      name: 'my-store',
    }
  )
);

In this setup:

  • The log middleware tracks state changes for debugging purposes.
  • The persist middleware ensures the state is saved to localStorage and restored on page reloads.

By combining middleware, you can build a store that’s both developer-friendly and resilient to page reloads.

By applying these strategies, you’ll not only enhance your application’s performance but also make it easier to maintain and extend as your project grows.
