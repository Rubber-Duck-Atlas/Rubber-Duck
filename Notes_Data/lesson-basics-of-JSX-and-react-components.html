JSX syntax and how it differs from HTML

JSX (JavaScript XML) is a syntax extension for JavaScript that allows you to write HTML-like code inside your JavaScript files. It’s one of the key features of React and makes building user interfaces more intuitive and readable.

Example:

const jsx = <h1>This is JSX</h1>;

At first glance, this looks like HTML, but it’s actually JavaScript. JSX allows you to seamlessly mix HTML and JavaScript, making it easier to define the structure and behavior of your UI components.

However, browsers don’t natively understand JSX because it’s not valid JavaScript. Tools like Babel are used to convert JSX into plain JavaScript that browsers can execute.

Differences Between JSX and HTML

Although JSX looks nearly identical to HTML, it’s important to understand that JSX is not HTML. It’s a JavaScript syntax extension that compiles down to React.createElement() calls. Because JSX lives inside JavaScript, there are several key differences in syntax and behavior.

Attributes Use CamelCase:

In JSX, attributes are written in camelCase instead of lowercase as in HTML.

<div className="container">Hello, World!</div>

Here, className is used instead of class because class is a reserved keyword in JavaScript.

Self-Closing Tags Must Be Explicit:

In JSX, all tags must be properly closed, even for elements like <img> or <input>.

<img src="logo.png" alt="Logo" />

Embedding JavaScript Expressions:

JSX allows you to embed JavaScript expressions inside curly braces {}. This is not possible in plain HTML.

const name = "React";
const element = <h1>Hello, {name}!</h1>;

JSX is Transpiled to JavaScript:

JSX is not understood by browsers directly. Tools like Babel transpile JSX into plain JavaScript.

const element = <h1>Hello, World!</h1>;

Transpiles to:

const element = React.createElement("h1", null, "Hello, World!");

JSX Can Only Have One Root Element:

A JSX expression must have a single root element. If you need multiple elements, wrap them in a parent container like <div> or a React Fragment (<>...</>).

const element = (
  <>
    <h1>Title</h1>
    <p>Content</p>
  </>
);

Methodology of JSX : Conversion to React.createElement

Under the hood, JSX is syntactic sugar for calling React.createElement. This function creates a JavaScript object that represents a DOM element or a React component.

Example:

Here’s a simple JSX example:

const jsx = <h1>This is JSX</h1>;

When Babel processes this code, it converts it into:

const jsx = React.createElement("h1", null, "This is JSX");

The React.createElement function takes three arguments:

  1. Type: The type of element to create (e.g., "h1", "div", or a custom React component).
  2. Props: An object containing attributes (like id, className, etc.) and event handlers (like onClick).
  3. Children: The content inside the element (e.g., text or nested elements).

The above React.createElement call produces an object like this:

{
  type: 'h1',
  props: {
    children: 'This is JSX'
  }
}

You can log this object to see its structure:

console.log(jsx);

This object is what React uses internally to render the actual DOM element.

Adding Attributes to JSX

When you add attributes to JSX elements, they are passed as the second argument (props) to React.createElement.

Example with Attributes:

const jsx = <h1 id="jsx">This is JSX</h1>;

This gets converted to:

const jsx = React.createElement("h1", { id: "jsx" }, "This is JSX");

The resulting object looks like this:

{
  type: 'h1',
  props: {
    id: 'jsx',
    children: 'This is JSX'
  }
}

Attributes like id, className, style, etc., are all part of the props object.

Handling Events

Event handlers like onClick are also included in the props object. For example:

JSX Code:

<button id="btn" onClick={() => console.log("clicked")}>
  Click Here
</button>

Converted Code:

React.createElement("button", { 
  id: "btn", 
  onClick: () => console.log("clicked") 
}, "Click Here");

The props object now includes the onClick handler:

{
  type: 'button',
  props: {
    id: 'btn',
    onClick: () => console.log("clicked"),
    children: 'Click Here'
  }
}

React automatically binds these event handlers to the corresponding DOM events during rendering.

Embedding Expressions in JSX

JSX allows you to embed JavaScript expressions inside curly braces {}. These expressions can include variables, function calls, arithmetic operations, and more. The result of the expression is rendered as part of the UI.

Examples:

Using Variables:

const name = "Alice";
const greeting = <h1>Hello, {name}!</h1>;

Using Arithmetic Operations:

const num1 = 5;
const num2 = 10;
const sum = <p>The sum is {num1 + num2}.</p>;

Calling Functions:

function formatName(user) {
  return `${user.firstName} ${user.lastName}`;
}
const user = { firstName: "John", lastName: "Doe" };
const welcomeMessage = <h1>Welcome, {formatName(user)}!</h1>;

Conditional Rendering:

  • You can use ternary operators or logical operators to conditionally render elements.
  • Example:
    const isLoggedIn = true;const message = <p>{isLoggedIn ? "Welcome back!" : "Please log in."}</p>;

Rendering Lists:

  • Use the .map() method to render lists of elements.
  • Example:
    const items = ["Apple", "Banana", "Cherry"];const list = (  <ul>    {items.map((item, index) => (      <li key={index}>{item}</li>    ))}  </ul>);

The Importance of the key Prop in React

When rendering lists of elements in React, the key prop is a special string attribute you need to include when creating lists of elements. Keys help React identify which items have changed, are added, or are removed. They give elements a stable identity, which is crucial for efficient updates and re-renders.

Importance of keys

  • Performance Optimization: Keys allow React to efficiently update the user interface by only re-rendering components that have changed rather than re-rendering the entire list.
  • Stable Identity: Keys provide a stable identity to each element in the list, helping React understand the relationship between the component and the DOM element.
  • Avoiding Bugs: Without keys, React might shuffle or incorrectly update elements, leading to subtle bugs and unexpected behavior.

Methodology

Keys should be:

  • Unique among siblings: Each key must be unique within the array of elements but doesn’t need to be globally unique.
  • Stable: The value of the key should not change between renders.
  • Predictable: Avoid using index as a key if the order of items may change, as it can lead to performance issues and bugs.

Example Without Keys

Let’s consider an example where we render a list without using keys:

const items = ["Apple", "Banana", "Cherry"];

function List() {
  return (
    <ul>
      {items.map((item) => (
        <li>{item}</li>
      ))}
    </ul>
  );
}

In this case, React will warn you in the console about missing keys. This is because React cannot efficiently manage and update individual list items.

Example With Keys

Now, let's improve the example by adding unique keys to each list item:

const items = [
  { id: 1, name: "Apple" },
  { id: 2, name: "Banana" },
  { id: 3, name: "Cherry" }
];

function List() {
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>{item.name}</li>
      ))}
    </ul>
  );
}

Here, each li element has a unique key attribute set to item.id. This helps React identify each list item distinctly, making the reconciliation process more efficient.

Best Practices for Using Keys

  1. Use IDs from Data: If your data comes from a database or an API, use unique identifiers (like id) as keys.
    const users = [  { id: '1', name: 'Alice' },  { id: '2', name: 'Bob' },  { id: '3', name: 'Charlie' }];function UserList() {  return (    <ul>      {users.map(user => (        <li key={user.id}>{user.name}</li>      ))}    </ul>  );}
  2. Avoid Using Index as Key: Using the array index as a key can cause issues if the list can change (e.g., items are added, removed, or reordered).
    // Not recommended if the list can changeconst items = ["Apple", "Banana", "Cherry"];function List() {  return (    <ul>      {items.map((item, index) => (        <li key={index}>{item}</li>      ))}    </ul>  );}
    In this example, using the index as a key might seem convenient, but it can lead to performance issues and bugs if the list changes frequently.
  3. Ensure Keys Are Unique: Always ensure that the keys are unique among siblings.
    const comments = [  { id: 'comment1', text: 'Great post!' },  { id: 'comment2', text: 'Thanks for sharing.' }];function CommentList() {  return (    <div>      {comments.map(comment => (        <div key={comment.id}>          <p>{comment.text}</p>        </div>      ))}    </div>  );}

Using Props and Basic State in Components

In React, components are the building blocks of your UI. They become powerful when they are dynamic—able to receive data (via props) and manage internal changes (via state). This section introduces both.

Props

  • Props (short for "properties") are inputs passed to a component. They allow you to make components reusable and dynamic.
  • Props are read-only and cannot be modified within the component.
  • Example:
    function Greeting(props) {  return <h1>Hello, {props.name}!</h1>;}const element = <Greeting name="Alice" />;
  • Destructuring Props:
    • You can destructure props for cleaner code.
    • Example:
      function Greeting({ name }) {  return <h1>Hello, {name}!</h1>;}

State

  • State represents data that can change over time within a component. Unlike props, state is managed internally by the component.
  • The useState hook is used to manage state in functional components.
  • Example:
    import React, { useState } from "react";function Counter() {  const [count, setCount] = useState(0);  return (    <div>      <p>Count: {count}</p>      <button onClick={() => setCount(count + 1)}>Increment</button>    </div>  );}

Overview of the React Component Lifecycle

React components don’t just render once and sit idle. They go through a lifecycle of stages from creation to removal.

Component Lifecycle

React components experience three primary lifecycle phases:

  1. Mounting: The component is being created and inserted into the DOM for the first time. This is where you typically initialize state and perform side effects like fetching data.
  2. Updating: Triggered when the component’s state or props change. React re-renders the component and may re-run side effects depending on dependencies.
  3. Unmounting: The component is removed from the DOM. This is where you clean up side effects (e.g., cancelling timers, aborting fetch requests).

Functional Components and Hooks:

Functional components use hooks like useEffect to handle lifecycle events.

Example:

import React, { useEffect, useState } from "react";
function LifecycleExample() {
  const [data, setData] = useState(null);
  useEffect(() => {
    console.log("Component mounted or updated");
    fetch("https://api.example.com/data")
      .then((response) => response.json())
      .then((result) => setData(result));
    return () => {
      console.log("Component will unmount");
    };
  }, []);
  return <div>{data ? <p>Data: {data}</p> : <p>Loading...</p>}</div>;
}

Ways State Updates Trigger Re-Renders

In React, state is a core feature that enables components to be dynamic and interactive. When the state of a component changes, React automatically re-renders the component to reflect the new state in the UI.

How React Handles State Updates and Re-Renders

  • State Changes Trigger Reconciliation: Whenever you call a state setter (like setCount), React schedules a re-render of that component. It doesn’t update the DOM directly but instead starts a reconciliation process.
  • Virtual DOM Optimization: React tracks changes using a virtual DOM. It compares the new virtual DOM with the previous one (a process called diffing) and applies only the minimal necessary changes to the actual DOM, ensuring better performance.
  • Component-Level Scope: Only the component whose state has changed, and its children, will be re-rendered. Sibling components or unrelated components are unaffected unless they share state via props or context.

Example

function Counter() {
  const [count, setCount] = React.useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}
  • Every time you click the button, setCount updates the state.
  • React re-renders the Counter component to display the new count.
  • Only the parts of the UI that use count are updated in the DOM.

Introduction to Basic Accessibility Considerations

Accessibility (often abbreviated as a11y) is about designing and developing applications that can be used by everyone, regardless of their abilities or disabilities. In modern web development, accessibility is not just a “nice-to-have”. It’s a fundamental requirement for building inclusive, effective, and legally compliant digital experiences.

Benefits Accessibility

  • Inclusive Design: Ensures that people with visual, auditory, motor, or cognitive impairments can use your application effectively.
  • Improved Usability: Accessibility improvements—like clear labels, keyboard navigation, and readable content—benefit all users, not just those with disabilities.
  • Better SEO: Search engines rely on semantic HTML and descriptive attributes, many of which overlap with accessibility best practices.
  • Legal Compliance: Following standards like WCAG (Web Content Accessibility Guidelines) helps organizations meet legal obligations and avoid discrimination lawsuits.
  • Wider Audience Reach: Making your application accessible means more people can use it, which can lead to increased traffic, customer satisfaction, and engagement.

Basic Accessibility Practices

Semantic HTML: Use semantic HTML elements like <header>, <main>, <footer>, <button>, etc., instead of generic <div> elements.

<button onClick={handleClick}>Submit</button>

ARIA Attributes: Use ARIA (Accessible Rich Internet Applications) attributes to enhance accessibility.

<div role="alert">This is an important message!</div>

Alt Text for Images Always provide descriptive alt text for images.

<img src="logo.png" alt="Company Logo" />

Keyboard Navigation: Ensure interactive elements like buttons and links are accessible via keyboard navigation.

Focus Management: Manage focus for modal dialogs and other dynamic content to ensure users with screen readers can navigate effectively.

Color Contrast: Ensure sufficient color contrast between text and background for readability.
