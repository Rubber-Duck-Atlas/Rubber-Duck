Lesson: Introduction to BERT, T5, and GPT

Introduction

Transformer-based models have transformed NLP by enabling large-scale transfer learning. In earlier lessons, you learned how Transformers process input sequences in parallel using self-attention and positional encoding. But their real power is revealed when they are pretrained on massive corpora and then fine-tuned on specific tasks.

This lesson introduces three foundational Transformer models—BERT, GPT, and T5—each with a distinct architecture and training philosophy. These models are not trained from scratch on every task. Instead, they are first pretrained on large unlabeled datasets to learn general language features and then fine-tuned on a smaller, task-specific dataset.

Understanding the architecture, training objectives, and use cases of BERT, GPT, and T5 will help you decide which model to use for tasks such as classification, summarization, question answering, and generation.

Learning Outcomes

By the end of this lesson, you will be able to:

  1. Compare the architectural and functional differences between BERT, GPT, and T5.
  2. Explain the pre-training objectives used in each model.
  3. Describe how fine-tuning enables these models to adapt to specific NLP tasks.

The BERT Model

To understand modern language representation models, we begin with BERT (Bidirectional Encoder Representations from Transformers), which is foundational to the development of T5 and GPT. This section explores BERT’s architecture and pretraining methodology, illustrating how it departs from traditional language models by introducing bidirectional attention and sentence-level reasoning.

Model Architecture

BERT is based solely on the Transformer encoder stack. Unlike autoregressive models (e.g., GPT) that process tokens in one direction, BERT incorporates context from both left and right simultaneously. This bidirectional design significantly improves performance on tasks requiring deep contextual understanding.

Key architectural elements include:

  • Transformer Encoder Stack: Multiple layers of multi-head self-attention and feed-forward sublayers.
  • Input Representation:
    • [CLS] token at the beginning for classification tasks.
    • [SEP] token to separate sentences in pairwise tasks.
    • Positional encodings and segment embeddings added to token embeddings.
  • Output: A sequence of contextual embeddings, with the [CLS] token embedding typically used for classification.

Pretraining Objectives

Masked Language Modeling (MLM) Masked Language Modeling (MLM) trains BERT-like models on unannotated text. 15% of tokens are manipulated: 80% replaced with [MASK], 10% with random tokens, 10% unchanged. The model predicts original tokens using subword tokenization, word/positional embeddings, and bidirectional transformers. Cross-entropy loss from manipulated tokens drives training, with all tokens used in self-attention.

  • Randomly masks some input tokens and trains the model to predict them.
  • Enables bidirectional understanding.

Example: Input: "So [mask] and [mask] for all apricot fish" Target: "long", "thanks", "the" Here, long, thanks and the have been sampled from the training sequence, with the first two masked and the replaced with the randomly sampled token apricot. Next Sentence Prediction (NSP) Next Sentence Prediction (NSP) in BERT models trains them to predict if two sentences are adjacent or unrelated (50% positive, 50% random pairs). It uses [CLS] and [SEP] tokens, plus segment embeddings, to process sentence pairs and support tasks like paraphrase detection and entailment.

  • Trains the model to determine whether a second sentence logically follows the first.
  • Helps the model understand relationships between sentences.Cross entropy calculates the NSP loss for each sentence pair input to the model. In BERT, the NSP loss is combined with the MLM objective to create the final loss. The following figure illustrates the NSP training process:

BERT Input Embeddings

BERT’s input representation is carefully designed to support both single-sentence and sentence-pair tasks within the same architecture. The final embedding for each token is a sum of three components:

Token Embeddings

  • These are standard word-piece embeddings derived from a pre-learned vocabulary.
  • BERT uses WordPiece tokenization, which splits words into subword units (e.g., "playing" → "play", "##ing").

Segment Embeddings

  • Used to differentiate between two sentences (A and B) when processing sentence pairs.
  • Tokens from the first sentence receive a segment ID of 0; tokens from the second sentence receive 1.

Positional Embeddings

  • Because Transformers do not process input sequentially, positional encodings are required to retain word order.
  • BERT uses learned positional embeddings (unlike the sinusoidal ones in the original Transformer paper).

The final input to the encoder is:

\[ \text{Input}_\text{Embedding} =\text{Token Embedding+Segment Embedding+Position Embedding} \]

Fine-Tuning BERT for Downstream Tasks

Once pretraining is complete, BERT can be fine-tuned for a wide range of NLP tasks by adding task-specific layers on top of the pretrained architecture.

General Fine-Tuning Procedure

  1. Add a lightweight output layer (e.g., softmax for classification, span extractor for QA).
  2. Initialize BERT with pretrained weights.
  3. Train the entire model (BERT + new layer) on a task-specific dataset with supervised labels.

Unlike earlier NLP pipelines that relied on frozen embeddings or task-specific architectures, BERT allows end-to-end learning with minimal task-specific modification.

Examples of Fine-Tuning Tasks

Task Type Input Format (Sentence A + B) Output Layer
Sentiment Analysis Single sentence Dense layer → softmax
Natural Language Inference Sentence pair (premise + hypothesis) Dense layer → softmax
Question Answering Paragraph + Question Span prediction over token indices

Why BERT’s Fine-Tuning is Powerful

  • Requires very little task-specific architecture engineering.
  • Makes it possible to achieve state-of-the-art performance on many benchmarks with only a few additional parameters.
  • Leverages bidirectional context, making it more powerful than traditional left-to-right or right-to-left language models.

Common Use Cases for BERT

BERT's flexible architecture and powerful bidirectional encoding make it suitable for a wide range of Natural Language Understanding (NLU) tasks. After fine-tuning, BERT has consistently set state-of-the-art benchmarks across the following applications:

Text Classification

BERT can be fine-tuned to classify text into categories such as:

  • Sentiment analysis (e.g., positive vs. negative movie reviews)
  • Topic classification (e.g., politics, sports, technology)

The [CLS] token embedding is typically passed through a softmax classifier for these tasks.

Named Entity Recognition (NER)

For sequence labeling tasks like NER, BERT is fine-tuned to make token-level predictions:

  • Recognizing entities such as names, locations, organizations (e.g., BIO tagging)
  • Handles context-sensitive disambiguation more effectively than traditional models

Question Answering (QA)

BERT excels in extractive QA tasks (e.g., SQuAD), where it is fine-tuned to identify:

  • The start and end positions of an answer span within a given passage
  • The model uses the entire context bidirectionally, improving accuracy in ambiguous questions

Sentence Pair Tasks

BERT was explicitly designed to model relationships between sentence pairs, supporting tasks such as:

  • Natural Language Inference (NLI): Determine if a hypothesis logically follows from a premise (e.g., entailment, contradiction, or neutral)
  • Paraphrase Detection and Semantic Textual Similarity (STS)

It does this by leveraging segment embeddings and encoding both sentences jointly.

By adapting BERT through minimal task-specific additions and end-to-end fine-tuning, researchers and practitioners can build powerful models for a wide spectrum of real-world applications in NLP.

While BERT has proven highly effective for understanding tasks through its bidirectional encoder architecture, another foundational model, GPT, was designed with a contrasting philosophy: text generation. GPT leverages the power of autoregressive modeling, using only the Transformer decoder to predict future tokens based on past context.

The GPT Model and Autoregressive Generation

GPT (Generative Pretrained Transformer) is a decoder-only Transformer trained to generate text by predicting the next word in a sequence. Unlike BERT, which processes input in both directions, GPT uses masked self-attention to ensure that each token only attends to earlier tokens, enabling left-to-right generation.

Key Properties of GPT

  • Architecture: Decoder-only Transformer with causal (masked) self-attention to prevent access to future tokens during training.
  • Input: A prompt or partial sentence (e.g., "The weather today is").
  • Output: The model predicts the next word (e.g., "sunny") and continues generation autoregressively.

Pretraining Objective

GPT learns using Causal Language Modeling, where the model predicts the next token without looking ahead. For training chatbots, the typical approach uses a standard causal language model architecture, where the model predicts each word based on all preceding words, employing the standard language modeling loss. The key distinction lies in the data, incorporating substantial conversation and pseudo-conversation data, as outlined earlier. As usual, the left context may encompass the entire prior conversation, limited only by the context window size. The following figure illustrates this training setup:

Applications of GPT

Building on its decoder-only architecture and ability to generate coherent, context-aware text, GPT models have been widely adopted across a variety of real-world tasks. Their autoregressive nature makes them especially powerful for tasks that involve sequence continuation, language generation, or prompt-based reasoning.

Common Use Cases

  • Story and Article Generation: GPT can generate human-like narratives, blog posts, summaries, and creative fiction based on a short prompt.
  • Conversational Agents and Chatbots: Its context-aware design allows GPT to drive natural, multi-turn conversations in customer service, virtual assistants, and interactive agents.
  • Few-Shot and Zero-Shot Learning: With larger models like GPT-3 and GPT-4, the model can perform tasks with minimal or no task-specific training—just by observing examples within a prompt.
  • Code Generation and Assistance: Specialized versions like Codex (used in tools such as GitHub Copilot) are fine-tuned on programming languages to assist with code generation, completion, and documentation.

These applications underscore GPT’s role as a general-purpose language model, bridging the gap between structured task learning and open-ended generation.

The T5 Model and the Text-to-Text Framework

Having explored how BERT excels at language understanding and GPT at generation, we now turn to a model that unifies both paradigms under a single, flexible architecture: T5 (Text-to-Text Transfer Transformer). Where BERT is trained to understand masked input and GPT is trained to predict future tokens, T5 reframes all NLP tasks classification, translation, summarization, question answering, as a text-to-text problem. This uniformity simplifies the training pipeline and enables the model to handle diverse tasks with the same architecture and objective.

Key Properties of T5

  • Architecture: A full encoder-decoder Transformer, enabling both input comprehension and output generation.
  • Input Format: Each task begins with a natural-language instruction (e.g., "translate English to German: Hello.") followed by the actual input.
  • Output Format: The corresponding target text (e.g., "Hallo.").

This framework promotes generalization across tasks and supports multitask learning.

Pretraining Objective

T5 is pretrained using a span corruption objective, a variation on masked language modeling:

  • Spans (contiguous sequences of tokens) are replaced by sentinel tokens such as <extra_id_0>.
  • The model learns to generate the missing spans in the output, enabling it to learn deep contextual representations and flexible text generation.

This strategy blends the strengths of BERT-style denoising and GPT-style decoding, preparing T5 for a wide range of downstream applications.

Example: Input: "summarize: The movie was long and boring, but the acting was good." Output: "The acting was good"

Applications of T5

The flexibility of the text-to-text framework enables T5 to excel across a wide range of NLP tasks. By expressing every problem as "input text → output text," T5 seamlessly adapts to various applications:

  • Text ClassificationTasks like sentiment analysis, topic classification, or spam detection are reformulated as:Input: "classify sentiment: The movie was amazing!"
    Output: "positive"
  • SummarizationGiven a document, T5 generates a concise summary:
    Input: "summarize: The article discusses the recent advancements in AI..."Output: "AI research is rapidly evolving."
  • TranslationMultilingual tasks are supported using prompts:
    Input: "translate English to French: I love programming"Output: "J'aime programmer"
  • Question AnsweringT5 supports extractive and generative QA:Input: "question: What is the capital of France? context: France is a country in Europe. Its capital is Paris."
    Output: "Paris"
  • Text Generation and ParaphrasingTasks such as rewriting or generating creative text fall within T5’s capabilities.

This versatility highlights why T5 has become a central model in many modern NLP systems, especially when paired with task-specific prompting strategies.

Key Observations

  • BERT is best suited for understanding tasks where deep bidirectional context is valuable.
  • GPT excels in generative tasks and few-shot learning via prompt engineering.
  • T5 offers the most versatility, unifying all tasks under a single "text-to-text" paradigm.

This comparative perspective helps clarify which model to choose depending on the task's requirements classification, generation, or multi-task flexibility.

Pre-training and Fine-tuning in NLP

In recent years, natural language processing (NLP) has shifted from building task-specific models from scratch to using large pre-trained language models. These models undergo a two-stage training paradigm: pre-training, where they learn general language representations from massive unlabeled text, and fine-tuning, where they are adapted to specific downstream tasks using labeled data. This approach has become the foundation for state-of-the-art performance across a wide range of NLP applications.

Pre-training

During pre-training, models are exposed to extensive text corpora to learn syntactic and semantic patterns of language. Depending on the model architecture, different pretraining objectives are used:

  • Masked Language Modeling (MLM) (e.g., BERT): A percentage of input tokens are masked, and the model is trained to predict them.
  • Autoregressive Language Modeling (e.g., GPT): The model predicts the next token given previous tokens in a sequence.
  • Span Corruption (e.g., T5): Spans of text are replaced with special tokens, and the model learns to reconstruct them.

These objectives enable the model to develop a contextual understanding of language that can generalize across tasks.

Fine-tuning

After pre-training, the model is fine-tuned on a specific task such as sentiment analysis, question answering, or named entity recognition. This involves:

  • Adding a task-specific output layer (e.g., a classification head).
  • Training the entire model, or just the output layers, using supervised data for the target task.
  • Typically requiring much less labeled data and fewer training iterations than training from scratch.

Fine-tuning aligns the general language knowledge acquired during pre-training with the specific requirements of the task at hand.

Benefits of the Paradigm

  • Data Efficiency: Reduces dependence on large labeled datasets for each new task.
  • Transferability: Pre-trained models can be reused across multiple NLP problems.
  • Performance: Achieves state-of-the-art results with less task-specific engineering.

This two-stage framework is now standard across modern NLP and underlies popular models such as BERT, GPT, RoBERTa, T5, and more.

Pretraining and finetuning. A pre-trained model can be fine-tuned to a particular domain, dataset, or task. There are many different ways to fine-tune, depending on exactly which parameters are updated from the fine-tuning data: all the parameters, some of the parameters, or only the parameters of specific extra circuitry.
