Building the Seq2Seq Model in TensorFlow/Keras

To deepen the understanding of Sequence-to-Sequence (Seq2Seq) models, we now turn to a practical implementation using TensorFlow and Keras. This hands-on example demonstrates how to build and train a basic Seq2Seq model for machine translation. Specifically, we will translate English sentences into their French equivalents using a simplified parallel corpus. While this example uses a small dataset for instructional clarity and reduced computational cost, the principles extend directly to large-scale systems.

Step 1: Preparing the Dataset

For this implementation, we use a small English–French parallel corpus in which each data point is a pair of aligned sentences: one in English (source) and the other in French (target). This type of dataset is commonly used for supervised machine translation tasks.

Characteristics of the Dataset

  • Parallel Format: Each English sentence has a corresponding French translation.
  • Token-Level Granularity: Sentences are tokenized into word or subword units before training.
  • Size: The dataset is intentionally kept small to facilitate rapid prototyping and demonstration.

Example Sentence Pair

# Sample dataset: English-French sentence pairs
# Each tuple contains (source sentence, target sentence)
data = [
    ('Good morning', 'bonjour'),
    ('how are you', 'comment ça va'),
    ('i am fine', 'je vais bien'),
    ('thank you', 'merci'),
    ('good night', 'bonne nuit')
]

Splitting and Marking the Data

We separate the English and French sentences and prepare the target sentences for decoding by adding special tokens.

# Separate the English and French sentences into two separate lists
input_texts, target_texts = zip(*data)

# Add special tokens to the target sentences:
# <sos> marks the start of the target sequence
# <eos> marks the end of the target sequence
# These tokens help the decoder know when to start and stop generating words
target_texts = ['<sos> ' + text + ' <eos>' for text in target_texts]

Role of <sos> and <eos>

  • <sos> (Start of Sequence): Signals the decoder to begin generation.
  • <eos> (End of Sequence): Indicates when to stop decoding.
  • These tokens are essential in training and inference, helping the model learn sequence boundaries.

Tokenizing the Text

Neural networks cannot operate on raw text; therefore, we convert each sentence into a sequence of integers using Keras' Tokenizer.

from tensorflow.keras.preprocessing.text import Tokenizer
from tensorflow.keras.preprocessing.sequence import pad_sequences

# Create tokenizers for both the input (English) and target (French) texts
# Setting filters='' disables the default character filtering, which removes punctuation/special characters
# This ensures special tokens like <sos> and <eos> are preserved
input_tokenizer = Tokenizer(filters='')
target_tokenizer = Tokenizer(filters='')

# Fit the tokenizers on the text to create the word-index mappings
# Each word gets assigned a unique integer
input_tokenizer.fit_on_texts(input_texts)
target_tokenizer.fit_on_texts(target_texts)

# Convert the sentences into sequences of integers
# e.g., "hello" -> [2] or "how are you" -> [3, 4, 5]
input_sequences = input_tokenizer.texts_to_sequences(input_texts)
target_sequences = target_tokenizer.texts_to_sequences(target_texts)

Padding the Sequences

All sequences must be padded to equal lengths for batching during training.

# Determine the maximum sequence lengths for padding
# Padding ensures that all sequences in a batch have the same length
max_input_len = max(len(seq) for seq in input_sequences)
max_target_len = max(len(seq) for seq in target_sequences)

# Pad the encoder input sequences (English) with zeros at the end (post-padding)
encoder_input_data = pad_sequences(input_sequences, maxlen=max_input_len, padding='post')

# For the decoder, we need two sets of data:
# 1. decoder_input_data: the input to the decoder at each time step (starts with <sos>)
# 2. decoder_target_data: the expected output from the decoder (ends with <eos>)

# We split target sequences:
# - decoder_input_data gets everything *except* the last token (<eos>)
# - decoder_target_data gets everything *except* the first token (<sos>)
# This offset helps the model learn to predict the next word
decoder_input_data = pad_sequences([seq[:-1] for seq in target_sequences],
                                   maxlen=max_target_len - 1, padding='post')

decoder_target_data = pad_sequences([seq[1:] for seq in target_sequences],
                                    maxlen=max_target_len - 1, padding='post')

Why the Shift?

This shifting technique supports teacher forcing, a training strategy where the model is guided using the actual target tokens rather than its own previous predictions. This accelerates learning and enhances convergence, especially in early training stages.

Step 2: Building the Training Model

With the dataset preprocessed and sequences prepared, we now construct the Seq2Seq model using TensorFlow and Keras. The architecture follows the classical Encoder–Decoder framework, where both encoder and decoder are composed of an Embedding layer followed by an LSTM layer. The final decoder output is produced using a dense (fully connected) layer with a softmax activation to generate token probabilities.

Setting Model Parameters

We begin by defining key hyperparameters and determining vocabulary sizes for both the source and target languages.

from tensorflow.keras.models import Model
from tensorflow.keras.layers import Input, LSTM, Embedding, Dense

# Latent dimensionality of the embedding space and LSTM units
latent_dim = 64

# Vocabulary sizes (+1 for padding token at index 0)
vocab_in_size = len(input_tokenizer.word_index) + 1  # English vocab size
vocab_out_size = len(target_tokenizer.word_index) + 1  # French vocab size

Defining the Encoder

The encoder reads the input sentence and encodes it into two state vectors: the final hidden state and cell state of the LSTM. These vectors summarize the input and are passed to the decoder to provide contextual understanding.

# Encoder input: a sequence of word indices (e.g., [2, 3, 4])
encoder_inputs = Input(shape=(None,))

# Embedding layer maps each word index to a dense vector
enc_emb = Embedding(input_dim=vocab_in_size, output_dim=latent_dim)(encoder_inputs)

# LSTM processes the embedded sequence and returns final states
# We discard the sequence output (_) and keep only the last hidden state (state_h) and cell state (state_c)
_, state_h, state_c = LSTM(latent_dim, return_state=True)(enc_emb)

# These states summarize the input and are passed to the decoder to provide context
encoder_states = [state_h, state_c]

Defining the Decoder

The decoder generates the output sequence step by step. It is initialized with the encoder's final states and uses teacher forcing during training.

# Decoder input: a sequence starting with <sos> followed by the expected output words
decoder_inputs = Input(shape=(None,))

# We define a separate embedding layer for the decoder
dec_emb_layer = Embedding(input_dim=vocab_out_size, output_dim=latent_dim)
dec_emb = dec_emb_layer(decoder_inputs)

# Decoder LSTM uses encoder's final states as initial state
# We keep return_sequences=True to output a sequence (word-by-word prediction)
decoder_lstm = LSTM(latent_dim, return_sequences=True, return_state=True)
decoder_outputs, _, _ = decoder_lstm(dec_emb, initial_state=encoder_states)

# Dense layer to convert LSTM output at each time step to a vocabulary-sized softmax output
decoder_dense = Dense(vocab_out_size, activation='softmax')
decoder_outputs = decoder_dense(decoder_outputs)

Compiling and Training the Model

We now compile the combined encoder–decoder model and train it using teacher forcing. Since the target output is a sequence of integer class labels (not one-hot encoded), we use sparse_categorical_crossentropy as the loss function.

# Define the full model that takes encoder and decoder inputs and outputs predicted tokens
model = Model([encoder_inputs, decoder_inputs], decoder_outputs)

# Compile with sparse categorical crossentropy because our target data consists of integer indices
model.compile(optimizer='adam', loss='sparse_categorical_crossentropy', metrics=['accuracy'])

# Fit the model
# Note: decoder_target_data[..., None] expands the last dimension to match shape (samples, timesteps, 1)
model.fit([encoder_input_data, decoder_input_data],
          decoder_target_data[..., None],
          epochs=300,
          verbose=0)

Key Concepts and Takeaways

  • Embedding Layers: Map tokens to dense vector spaces that capture semantic relationships.
  • Encoder LSTM: Processes the entire input sequence and outputs the final hidden and cell states, which serve as context for decoding.
  • Decoder LSTM: Initialized with the encoder’s states and generates the target sequence one token at a time.
  • Teacher Forcing: During training, the decoder receives the true previous token as input rather than its own prediction, helping the model converge faster.
  • Sparse Categorical Loss: Efficient for handling integer-encoded class labels, avoiding the need for one-hot encoding.

After training, the model is expected to perform basic translation tasks on short English input sequences. The next step is to build inference models to generate translations at test time.

Step 3: Inference and Decoding

Once the Seq2Seq model has been trained, it must be adapted for inference—i.e., generating translations or output sequences one token at a time. During training, the model has access to the entire target sequence through teacher forcing. In contrast, inference requires the decoder to generate one token at a time, feeding each predicted word back into itself until the full sequence is produced.

Creating the Inference Models

At inference time, the model is split into two components:

  1. Encoder Inference Model: Encodes the input sequence and returns the final LSTM states.
  2. Decoder Inference Model: Takes the previously predicted token and the previous LSTM states to predict the next token.
# Encoder inference model: same structure as training encoder
# Takes an input sequence and outputs internal LSTM states
encoder_model = Model(encoder_inputs, encoder_states)

# Decoder inference requires feeding previous state manually
decoder_state_input_h = Input(shape=(latent_dim,))
decoder_state_input_c = Input(shape=(latent_dim,))
decoder_states_inputs = [decoder_state_input_h, decoder_state_input_c]

# Decoder will now take only one timestep at a time (i.e., one word input)
decoder_inputs_single = Input(shape=(1,))  # shape = (batch_size, 1)
dec_emb2 = dec_emb_layer(decoder_inputs_single)

# Use the same LSTM and Dense layers from training
# Initialize decoder LSTM with previous states
decoder_outputs2, state_h2, state_c2 = decoder_lstm(dec_emb2, initial_state=decoder_states_inputs)
decoder_outputs2 = decoder_dense(decoder_outputs2)

# Final inference decoder model
# Inputs: current word + previous states
# Outputs: predicted word + new states
decoder_model = Model(
    [decoder_inputs_single] + decoder_states_inputs,
    [decoder_outputs2, state_h2, state_c2]
)

Defining the Translation Function

The decoding function works as follows:

  1. Encodes the input using the encoder model.
  2. Initializes the decoder with the <sos> token.
  3. Iteratively predicts one token at a time using the decoder model.
  4. Stops when the <eos> token is produced or when a maximum length is reached.
import numpy as np

# Reverse mapping from token index to word for the target language
reverse_target_word_index = {v: k for k, v in target_tokenizer.word_index.items()}

# Get integer values of the special tokens
sos_token = target_tokenizer.word_index['<sos>']
eos_token = target_tokenizer.word_index['<eos>']

def decode_sequence(input_seq):
    # Encode the input as state vectors
    states_value = encoder_model.predict(input_seq)

    # Generate empty target sequence with just the <sos> token
    target_seq = np.array([[sos_token]])

    decoded_sentence = []
    stop_condition = False

    while not stop_condition:
        # Predict the next word and updated states
        output_tokens, h, c = decoder_model.predict([target_seq] + states_value)

        # Choose the most likely next word (highest probability)
        sampled_token_index = np.argmax(output_tokens[0, -1, :])
        sampled_word = reverse_target_word_index.get(sampled_token_index, '')

        # Exit condition: either <eos> token or max length reached
        if sampled_token_index == eos_token or len(decoded_sentence) > max_target_len:
            stop_condition = True
        else:
            decoded_sentence.append(sampled_word)

        # Update target_seq to contain the last predicted word
        target_seq = np.array([[sampled_token_index]])

        # Update states for next iteration
        states_value = [h, c]

    return ' '.join(decoded_sentence)

Example: Translating a Sentence

We now use the trained model to translate a new input sentence from English to French.

test_input = 'thank you'

# Convert input sentence to sequence and pad to expected length
test_seq = input_tokenizer.texts_to_sequences([test_input])
test_seq = pad_sequences(test_seq, maxlen=max_input_len, padding='post')

# Generate translation
print("Input:", test_input)
print("Predicted Translation:", decode_sequence(test_seq))

Expected Output

Input: thank you
Predicted Translation: merci

Summary

  • Inference separates the training model into encoder and decoder components.
  • The decoder predicts one word at a time, using its own output as input for the next timestep.
  • This approach closely mimics real-world usage, such as translating text or generating summaries without access to the full output during generation.

Step 4: BLEU Score Evaluation

To evaluate the performance of a machine translation model, it is essential to use a quantitative metric that reflects the quality of the predicted translations. One of the most widely adopted metrics in this context is BLEU (Bilingual Evaluation Understudy). BLEU measures how closely the model’s output (the hypothesis) matches one or more correct reference translations.

Understanding BLEU

  • BLEU Score Range: 0 to 1 (or 0% to 100%).
  • Higher Scores: Indicate a closer match to the reference translation.
  • Lower Scores: Reflect poor correspondence in terms of word choice and order.
  • N-gram Matching: BLEU uses precision over n-grams (typically unigrams to 4-grams) to quantify similarity between hypothesis and reference.

BLEU is particularly useful in evaluating models that generate natural language output, such as in machine translation, text summarization, and dialogue generation.

Evaluating Sentence-Level BLEU Scores

We apply sentence-level BLEU evaluation using nltk.translate.bleu_score. Below is a minimal example using the test sentences from our toy dataset.

from nltk.translate.bleu_score import sentence_bleu

# Reference French translations (ground truth)
references = [['merci'], ['comment ça va']]

# Corresponding English test inputs
tests = ['thank you', 'how are you']

# Evaluate each sentence
for sentence, ref in zip(tests, references):
    # Tokenize and pad the input sentence
    seq = input_tokenizer.texts_to_sequences([sentence])
    seq = pad_sequences(seq, maxlen=max_input_len, padding='post')

    # Generate prediction using the model
    hyp = decode_sequence(seq)

    # Display input, hypothesis and BLEU score
    print(f"Input: {sentence}")
    print(f"Hypothesis: {hyp}")
    print("BLEU:", sentence_bleu([ref], hyp.split()))

Sample Output

Input: thank you  
Hypothesis: merci  
BLEU: 1.0

Input: how are you  
Hypothesis: comment ça va  
BLEU: 1.0

These results indicate perfect matches between the predicted and reference translations, achievable in this case due to the small and deterministic nature of the dataset.

Remarks and Extensions

  • Toy Dataset Performance: The high BLEU scores here are expected, as the model was trained and evaluated on a small, closed dataset with minimal variation.
  • Scalability: On real-world datasets, BLEU scores will vary and tend to be much lower, reflecting the challenges of generating fluent and accurate translations across diverse linguistic constructs.
  • Corpus-Level BLEU: For broader evaluation, BLEU can be computed across an entire corpus to assess overall model quality.
  • Complementary Metrics: BLEU is often used alongside metrics like METEOR, ROUGE, or chrF to capture fluency, recall, and character-level variation.
