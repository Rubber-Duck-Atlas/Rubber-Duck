Lesson: Why Global State? Introducing Zustand

Introduction

In the ever-evolving world of frontend development, managing state effectively is crucial for building dynamic and responsive user interfaces. Whether you're toggling a button, tracking form inputs, or synchronizing data across multiple components, understanding how to manage state can make or break your application's performance and maintainability. In this lesson, we’ll explore the concept of local state, its best use cases, and its limitations. We’ll also delve into global state management solutions like Redux, MobX, and Zustand, equipping you with the tools to handle both simple and complex state requirements in your projects.

Learning Outcomes

By the end of this lesson, you will:

  1. Gain a clear understanding of what local state is, when to use it, and how it simplifies component-specific logic.
  2. Recognize scenarios where local state becomes insufficient and learn how to address these challenges.
  3. Discover popular global state management tools like Redux, MobX, and Zustand, and understand their unique strengths.
  4. Learn how to set up and integrate global state management libraries in React applications, enabling you to build scalable and maintainable apps.
  5. Understand the distinctions between local, global, and remote state, and know when to apply each type in your projects.

Steps to Identify the Need for Global State:

  1. Determine which pieces of data are needed by multiple components or across different parts of the app.
  2. Assess whether prop drilling or other workarounds are becoming too cumbersome.
  3. Check if the state needs to persist across routes or sessions.
  4. Think about how the application might grow and whether local state will scale effectively.

Tools for Managing Global State:

  • Redux: A predictable state container that enforces strict rules for state updates, making it ideal for large-scale applications.
  • MobX: A simpler, more flexible alternative that allows direct state mutation and automatic dependency tracking.

Understanding Redux

Redux is a predictable state container for JavaScript applications. It operates on three core principles:

  1. Single Source of Truth: The entire application state is stored in a single object called the Store.
  2. Read-Only State: State is immutable and can only be updated by dispatching actions.
  3. Changes via Pure Functions: Reducers are pure functions that specify how the state should change based on actions.

These principles make Redux highly predictable and scalable, especially for large applications. Redux also provides powerful debugging tools like the Redux DevTools, which simplify debugging and state inspection.

Setting Up Redux in a ReactJS App

To integrate Redux with React, you use the React-Redux library. Here’s a step-by-step breakdown:

  1. Creating the Store
    // store.jsimport { createStore } from 'redux';import rootReducer from './reducers';const store = createStore(rootReducer);export default store;
    The createStore function initializes the Redux store, which holds the application state. The rootReducer combines all reducers into a single reducer.
  2. Defining Reducers
    // reducers.jsimport { combineReducers } from 'redux';import counterReducer from './counterReducer';const rootReducer = combineReducers({  counter: counterReducer,});export default rootReducer;
    The combineReducers utility merges multiple reducers into one, enabling modular state management.
  3. Implementing a Reducer
    // counterReducer.jsconst initialState = { count: 0 };const counterReducer = (state = initialState, action) => {  switch (action.type) {    case 'INCREMENT':      return { ...state, count: state.count + 1 };    case 'DECREMENT':      return { ...state, count: state.count - 1 };    default:      return state;  }};export default counterReducer;
    This reducer handles actions (INCREMENT, DECREMENT) and updates the state accordingly.
  4. Connecting Components to the Store
    // Counter.jsimport { connect } from 'react-redux';const Counter = ({ count, increment, decrement }) => (  <div>    <h1>{count}</h1>    <button onClick={increment}>+</button>    <button onClick={decrement}>-</button>  </div>);const mapStateToProps = (state) => ({  count: state.counter.count,});const mapDispatchToProps = (dispatch) => ({  increment: () => dispatch({ type: 'INCREMENT' }),  decrement: () => dispatch({ type: 'DECREMENT' }),});export default connect(mapStateToProps, mapDispatchToProps)(Counter);
    • Explanation:This component displays the current count and provides buttons to increment or decrement it. It connects to the Redux store using connect:
      • mapStateToProps: Maps the Redux state (state.counter.count) to the component's props (count), allowing the component to access the state.
      • mapDispatchToProps: Maps dispatch functions to props (increment and decrement), enabling the component to trigger actions.
      • connect ties everything together, making the component aware of the Redux store.

Exploring MobX

MobX is a simpler and more intuitive alternative to Redux. It is based on the principles of observables and reactions:

  • Observables: Values that can be tracked for changes.
  • Reactions: Functions that automatically update when an observable value changes.

MobX requires less boilerplate code and allows direct state mutation, making it ideal for smaller or medium-sized applications. It also includes built-in performance optimizations, ensuring efficiency even in large-scale apps.

Using MobX in a ReactJS App

MobX integrates seamlessly with React through the mobx-react library. Here’s an example:

  1. Defining the Store
    // store.jsimport { observable, action } from 'mobx';class CounterStore {  @observable count = 0;  @action increment() {    this.count++;  }  @action decrement() {    this.count--;  }  @action reset() {    this.count = 0;  }}const counterStore = new CounterStore();export default counterStore;
    The @observable decorator makes the count property trackable, while @action methods define how the state can be modified.
  2. Creating a Reactive Component
    // Counter.jsimport { observer } from 'mobx-react';import counterStore from './store';const Counter = observer(() => {  const { count, increment, decrement } = counterStore;  return (    <div>      <h1>{count}</h1>      <button onClick={increment}>+</button>      <button onClick={decrement}>-</button>    </div>  );});export default Counter;
    • Explanation:This is a reactive component that automatically updates when the count observable changes:
      • observer: Wraps the component to make it reactive. Whenever count changes, the component re-renders.
      • The component directly accesses the counterStore to get the count and call increment/decrement.

Understanding Zustand

Zustand is a small, fast, and scalable state management solution for React applications. Created by Jared Palmer and Daishi Kato, Zustand offers a simple and intuitive API that makes state management less cumbersome compared to other solutions.

Types of State

Before diving deeper into Zustand, let's understand the different types of state in web applications:

  • Local State: State that is specific to a component and doesn't need to be shared with other parts of the application.
  • Global State: State that needs to be accessed and modified by multiple components across the application.
  • Remote State: State that represents data fetched from an external source, typically an API.

Getting Started with Zustand

To start using Zustand, first install it via npm, yarn, or pnpm:

npm install zustand
# or
yarn add zustand
# or
pnpm add zustand

Implementing Zustand

Let's look at a basic implementation of Zustand:

import { create } from 'zustand';

const useStore = create((set) => ({
  bears: 0,
  increasePopulation: () => set((state) => ({ bears: state.bears + 1 })),
  removeAllBears: () => set({ bears: 0 }),
}));

function BearCounter() {
  const bears = useStore((state) => state.bears);
  return <h1>{bears} around here...</h1>;
}

function Controls() {
  const increasePopulation = useStore((state) => state.increasePopulation);
  return <button onClick={increasePopulation}>one up</button>;
}

In this example, we create a store with a bears state and two actions to modify it. The BearCounter and Controls components can then access and modify the state using the useStore hook.

Conclusion

State management is a cornerstone of modern frontend development, and mastering it empowers you to create efficient, scalable, and user-friendly applications. While local state is perfect for handling isolated, component-specific data, transitioning to global state becomes essential as your application grows in complexity. Tools like Redux, MobX, and Zustand offer powerful yet flexible solutions for managing shared and persistent data across your app.
