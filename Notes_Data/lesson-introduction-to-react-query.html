Lesson: Introduction to React Query

Introduction

React Query is a powerful JavaScript library designed to simplify data fetching, caching, and state management in modern React applications. By providing a declarative API through hooks like useQuery and useMutation, it eliminates the need for boilerplate code and manual synchronization of asynchronous data. This lesson explores the core features of React Query, including automatic caching, background data syncing, optimistic updates, and error handling. Through practical examples and comparisons with traditional data-fetching methods, you’ll learn how React Query enhances developer productivity and application performance.

Learning Outcomes

By the end of this lesson, you will be able to:

  1. Understand the purpose and benefits of using React Query in React applications.
  2. Implement data fetching and caching using useQuery and manage mutations with useMutation.
  3. Configure caching options like cacheTime and staleTime to optimize performance.
  4. Handle loading states, errors, and retries effectively with minimal boilerplate code.
  5. Differentiate React Query from manual data-fetching approaches (e.g., fetch or axios) and appreciate its advantages.
  6. Apply React Query to real-world scenarios such as pagination, optimistic updates, and periodic re-fetching.

Understanding React Query

React Query is a JavaScript library designed to handle the complexities of data fetching and caching in modern React applications. Offering a set of hooks and utilities allows developers to manage remote data effortlessly. With React Query, you can declaratively fetch, cache, and update data without writing boilerplate code for state management or manual synchronization. React Query is more than just a data-fetching library—it’s a complete solution for managing asynchronous data in React applications. Its built-in caching, background syncing, and optimistic updates make it an invaluable tool for developers building modern web apps. By reducing boilerplate code and handling complex state management under the hood, React Query allows you to focus on what truly matters: delivering a great user experience.

Features of React Query

  1. Declarative Data Fetching: React Query promotes a declarative approach to data fetching using hooks like useQuery and useMutation. This leads to cleaner, more organized code that’s easier to maintain.
  2. Automatic Caching: Built-in caching ensures that query results are stored and reused efficiently. When mutations occur, React Query automatically updates the cache, ensuring your UI remains consistent.
  3. Background Data Sync: React Query can refetch data in the background, keeping your data fresh without requiring manual intervention. This is particularly useful for real-time applications.
  4. Pagination and Infinite Scrolling: The library provides utilities to handle pagination and infinite scrolling with minimal effort, making it ideal for apps that display large datasets.
  5. Optimistic Updates: Optimistic updates allow you to make your app feel faster and more responsive by updating the UI immediately before the server confirms the change.

Getting Started with React Query

Let’s dive into a basic example to see how easy it is to get started with React Query. First, install the library using npm:

npm install @tanstack/react-query

Next, set up the QueryClientProvider to make React Query available throughout your application. You can configure this in your index.tsx file (or index.js if you’re not using TypeScript):

import React from 'react';
import ReactDOM from 'react-dom/client';
import './index.css';
import App from './App';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

const root = ReactDOM.createRoot(document.getElementById('root') as HTMLElement);

// Create a QueryClient instance
const queryClient = new QueryClient();

root.render(
  <QueryClientProvider client={queryClient}>
    <App />
  </QueryClientProvider>
);

With the provider set up, you can now use React Query hooks in your components. Let’s look at an example in App.tsx:

import React from 'react';
import { useQuery } from '@tanstack/react-query';

function App() {
  // Fetch user data using useQuery
  const userData = useQuery(['users'], () =>
    fetch('https://jsonplaceholder.typicode.com/users').then((response) => response.json()),
    {
      enabled: false, // Disable automatic fetching on mount
    }
  );

  return (
    <div>
      <button onClick={() => userData.refetch()}>Get Users</button>
      <div>
        {userData.isFetching && <div>Fetching user data...</div>}
        {userData.isError && <div>Error fetching data!</div>}
        {userData.data?.length > 0 &&
          userData.data.map((user: any) => <div key={user.id}>{user.name}</div>)}
      </div>
    </div>
  );
}

export default App;

Explanation:

  • The useQuery hook fetches a list of users from the API.
  • The enabled: false option prevents the query from running automatically when the component mounts. Instead, the user must click the "Get Users" button to trigger the fetch.
  • React Query handles loading (isFetching), error (isError), and data states (data) behind the scenes, eliminating the need for manual state management.

Data Fetching with React Query

React Query simplifies the process of fetching data from APIs by providing hooks like useQuery. Unlike traditional approaches such as useEffect, React Query optimizes data fetching by returning cached data first (if available) before making a network request. It also seamlessly handles loading and error states.

Example: Fetching Posts from an API

Here’s an example of fetching posts using React Query:

import { useQuery } from '@tanstack/react-query';
import axios from 'axios';

const fetchPosts = async () => {
  const { data } = await axios.get('https://jsonplaceholder.typicode.com/posts');
  return data;
};

function Posts() {
  const { data, isLoading, isError, error } = useQuery(['posts'], fetchPosts);

  if (isLoading) return <div>Loading...</div>;
  if (isError) return <div>Error! {error.message}</div>;

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {data.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}

export default Posts;

Features of useQuery:

  • Query Key: A unique identifier (['posts']) used to cache and track the query result.
  • Query Function: The function (fetchPosts) responsible for fetching data.
  • State Management: Automatically handles loading (isLoading), errors (isError), and data (data).

Explanation:

  • The useQuery hook initiates a data fetch using the fetchPosts function.
  • While the data is being fetched, the component displays a loading message. If an error occurs, it shows an error message.
  • Once the data is successfully fetched, it renders a list of posts.

Caching Data with React Query

Caching is a feature of React Query, enabling efficient storage and reuse of data to minimize redundant network requests and enhance application performance. By intelligently managing cached data, React Query ensures that your application remains responsive and reduces unnecessary server load.

Caching Methodology in React Query

React Query employs a robust caching mechanism that balances between serving fresh data and minimizing unnecessary re-fetches. Here’s a detailed breakdown of how it works:

Initial Request

When the useQuery hook is invoked, React Query performs the following steps:

  • It checks if data corresponding to the provided queryKey exists in the cache.
    • If cached data is found, it is returned immediately, avoiding an additional network request.
    • If no cached data is available, React Query executes the queryFn (a function responsible for fetching data) to retrieve the data from the server.

Stale vs Fresh Data

React Query distinguishes between fresh and stale data to optimize performance:

  • Fresh Data: Data is considered "fresh" during the staleTime period. During this time, React Query serves the data directly from the cache without triggering a re-fetch.
  • Stale Data: Once the staleTime elapses, the data is marked as "stale." While stale data can still be served to the user, React Query will attempt to re-fetch it in the background to ensure the data remains up-to-date.

Cache Time and Stale Time

Two key configuration options govern React Query's caching behavior:

  • cacheTime: Defines how long unused or inactive data remains in the cache before being garbage-collected. The default value is 5 minutes.
  • staleTime: Specifies the duration after which data is marked as stale but still usable. The default value is 0 seconds, meaning data is stale immediately after being fetched.

Example: Configuring Cache Options

Below is an example demonstrating how to configure caching options using React Query:

const { data, isLoading, isError } = useQuery({
  queryKey: ['books'], // Unique key for the query
  queryFn: fetchData,  // Function to fetch data
  cacheTime: 60000,    // Retain unused data in the cache for 60 seconds
  staleTime: 30000,    // Mark data as stale after 30 seconds
});

Explanation:

  • cacheTime: 60000: Ensures that the data remains in the cache for 60 seconds after it is no longer actively used by any component. After this period, the data is removed from the cache.
  • staleTime: 30000: Specifies that the data should be considered stale after 30 seconds. Once stale, React Query will attempt to re-fetch the data in the background when the query is active again.

Re-Fetching Data with React Query

Re-fetching ensures that your application stays up-to-date with the latest data from the server. React Query provides several mechanisms for re-fetching:

Background Re-Fetching

When data becomes stale, React Query automatically re-fetches it in the background without interrupting the user experience.

Periodic Re-Fetching

You can configure React Query to periodically re-fetch data using the refetchInterval option:

const { data, isLoading, isError } = useQuery({
  queryKey: ['books'],
  queryFn: fetchData,
  refetchInterval: 120000, // Re-fetch every 2 minutes
});

Explanation: The refetchInterval ensures that data is re-fetched every 2 minutes, keeping the client synchronized with the server.

Manual Re-Fetching

React Query also allows manual re-fetching through the refetch function:

const { data, isLoading, isError, refetch } = useQuery(['books'], fetchData);

return (
  <div>
    <button onClick={() => refetch()}>Refresh Data</button>
    {isLoading ? <div>Loading...</div> : <div>{data}</div>}
  </div>
);

Explanation: The refetch function allows users to manually trigger a data fetch, useful for scenarios like refreshing a page or updating specific components.

Mutations for Data Updates

While useQuery focuses on fetching and caching data, useMutation is used for creating, updating, or deleting data. It supports optimistic updates and rollback mechanisms in case of errors.

Example: Creating a New Post

import { useMutation } from '@tanstack/react-query';
import axios from 'axios';

function Post() {
  const [title, setTitle] = useState('');
  const [description, setDescription] = useState('');

  const { mutate, isLoading, isError, error } = useMutation(createPost, {
    retry: 3, // Retry up to 3 times on failure
  });

  const createPost = async () => {
    const response = await axios.post('https://jsonplaceholder.typicode.com/posts', {
      title,
      description,
    });
    return response.data;
  };

  return (
    <div>
      <input value={title} onChange={(e) => setTitle(e.target.value)} />
      <input value={description} onChange={(e) => setDescription(e.target.value)} />
      <button onClick={() => mutate({ title, description })}>Create Post</button>
      {isLoading && <div>Saving...</div>}
      {isError && <div>Error: {error.message}</div>}
    </div>
  );
}

Explanation:

  • The useMutation hook manages the creation of a new post.
  • The mutate function triggers the POST request, while isLoading and isError handle loading and error states.

Difference Between React Query and Manual fetch/axios

When working with data fetching in React applications, developers traditionally rely on manual approaches using fetch or axios. While these methods are effective for basic use cases, they often lead to increased complexity and repetitive code when managing asynchronous data operations like caching, re-fetching, and error handling. In contrast, React Query abstracts these complexities into a streamlined API, significantly improving developer productivity and application performance.

Manual Data Fetching with fetch/axios

Example: Fetching Data Using axios

import React, { useState, useEffect } from 'react';
import axios from 'axios';

function Posts() {
  const [data, setData] = useState([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const fetchData = async () => {
      try {
        const response = await axios.get('https://jsonplaceholder.typicode.com/posts');
        setData(response.data);
        setIsLoading(false);
      } catch (err) {
        setError(err.message);
        setIsLoading(false);
      }
    };

    fetchData();
  }, []);

  if (isLoading) return <div>Loading...</div>;
  if (error) return <div>Error: {error}</div>;

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {data.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
}

export default Posts;

Characteristics of Manual Data Fetching:

  • Boilerplate Code: Developers must manually handle state management (useState) and side effects (useEffect).
  • Error Handling: Requires explicit error handling logic.
  • Caching and Re-fetching: Developers need to implement custom logic for caching, background updates, and stale data management.
  • Reusability: Code is often tightly coupled to specific components, making it less reusable.

Explanation:

  • The useEffect hook triggers the data fetch when the component mounts.
  • The useState hook manages loading, error, and data states.
  • This approach requires significant effort to implement advanced features like caching, retries, and background updates.

Asynchronous Operations in React

Asynchronous operations are essential for fetching data from APIs, performing computations, or interacting with external services. In React, these operations are typically handled using async/await or Promises. However, managing the lifecycle of asynchronous operations—such as loading states, error handling, and data updates—can be challenging without proper tools.

In a React application, asynchronous operations are often required to fetch or update data dynamically. For example:

  • Fetching data from a REST API or GraphQL endpoint.
  • Handling user-triggered actions like form submissions.
  • Performing background computations or integrating with third-party services.

While JavaScript's async/await and Promises provide a clean way to handle asynchronous logic, React developers must also manage:

  1. Loading States: Indicating to users that data is being fetched.
  2. Error Handling: Displaying meaningful error messages when something goes wrong.
  3. Data Updates: Ensuring the UI reflects the latest data after an operation completes.

Without proper management, these tasks can lead to complex and error-prone code.

Challenges in Managing Asynchronous Operations:

  • Loading States: Users need feedback while data is being fetched.
  • Error Handling: Gracefully handling errors ensures a better user experience.
  • Data Updates: Keeping the client synchronized with the server requires efficient re-fetching and caching mechanisms.

Using async/await with useState and useEffect

The most basic approach involves combining async/await with React's state and effect hooks:

import { useState, useEffect } from 'react';

function useFetchData(url) {
  const [data, setData] = useState(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const fetchData = async () => {
      try {
        setIsLoading(true);
        const response = await fetch(url);
        if (!response.ok) throw new Error('Failed to fetch data');
        const result = await response.json();
        setData(result);
      } catch (err) {
        setError(err.message);
      } finally {
        setIsLoading(false);
      }
    };

    fetchData();
  }, [url]);

  return { data, isLoading, error };
}

Explanation:

  • The useFetchData hook encapsulates the logic for fetching data, managing loading states, and handling errors.
  • While functional, this approach requires boilerplate code for every asynchronous operation.

Managing Loading States

Loading states inform users that data is being fetched, improving the perceived performance of the application. React Query provides built-in support for managing loading states through the isLoading property returned by the useQuery hook.

Example: Managing Loading States with React Query and TypeScript

import React from 'react';
import { useQuery } from '@tanstack/react-query';
import axios from 'axios';

interface Post {
  id: number;
  title: string;
}

const fetchPosts = async (): Promise<Post[]> => {
  const { data } = await axios.get('https://jsonplaceholder.typicode.com/posts');
  return data;
};

const Posts: React.FC = () => {
  const { data, isLoading, isError, error } = useQuery<Post[], Error>(['posts'], fetchPosts);

  if (isLoading) {
    return <div>Loading...</div>;
  }

  if (isError) {
    return <div>Error: {error.message}</div>;
  }

  return (
    <div>
      <h1>Posts</h1>
      <ul>
        {data?.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </div>
  );
};

export default Posts;

Features:

  • Type Safety: The useQuery hook is typed with Post[] for the data and Error for the error, ensuring type safety throughout the component.
  • Loading Indicator: The isLoading property is used to display a loading message while the data is being fetched.

Explanation:

  • The fetchPosts function fetches data from the API and returns it as an array of Post objects.
  • The useQuery hook manages the loading state (isLoading) and error state (isError), allowing the component to render appropriate feedback to the user.

Error Handling in React (TypeScript)

Error handling is critical for providing a seamless user experience. React Query simplifies error handling by providing the isError property and the error object, which can be used to display meaningful error messages.

Example: Error Handling with React Query and TypeScript

import React from 'react';
import { useQuery } from '@tanstack/react-query';
import axios from 'axios';

interface Book {
  id: number;
  title: string;
  author: string;
}

const fetchBooks = async (): Promise<Book[]> => {
  const { data } = await axios.get('https://api.example.com/books');
  if (!data) {
    throw new Error('Failed to fetch books');
  }
  return data;
};

const Books: React.FC = () => {
  const { data, isLoading, isError, error } = useQuery<Book[], Error>(['books'], fetchBooks);

  if (isLoading) {
    return <div>Loading...</div>;
  }

  if (isError) {
    return <div>Error: {error.message}</div>;
  }

  return (
    <div>
      <h1>Books</h1>
      <ul>
        {data?.map((book) => (
          <li key={book.id}>
            <h2>{book.title}</h2>
            <p>{book.author}</p>
          </li>
        ))}
      </ul>
    </div>
  );
};

export default Books;

Features:

  • Error Object: The error object provides detailed information about the error, such as the error message.
  • Graceful Degradation: The component gracefully handles errors by displaying an error message instead of crashing.

Explanation:

  • The fetchBooks function throws an error if the API response is invalid, ensuring that the error is propagated to the useQuery hook.
  • The isError property is used to conditionally render an error message, improving the user experience.
