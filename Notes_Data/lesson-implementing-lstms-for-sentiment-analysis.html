Lesson: Implementing LSTMs for Sentiment Analysis

Introduction

Sentiment analysis is a foundational task in natural language processing where the goal is to classify the emotional tone of a text as positive, negative, or neutral. Simple models like bag-of-words fail to capture sequential information or context, often leading to poor performance, especially on longer texts.

Long Short-Term Memory (LSTM) networks are well-suited for this task. As covered in the previous lesson, LSTMs are designed to retain information over long sequences and are capable of learning dependencies between distant words. This makes them an ideal architecture for sequence classification tasks like sentiment analysis.

In this lesson, we will explore how LSTMs are applied to sentiment classification, understand how data is prepared for input into LSTMs, and examine how hyperparameter tuning can affect model performance.

Learning Outcomes

By the end of this lesson, you will be able to:

  1. Describe how LSTMs are used for sequence classification in NLP.
  2. Interpret how input sequences are represented and fed into an LSTM model.
  3. Analyze the effect of hyperparameters on LSTM model performance.

Introduction to sentiment classification

Sentiment analysis is a classic natural language processing task where the goal is to determine the emotional tone behind a body of text. In its simplest form, the task is binary: classify a piece of text as expressing either positive or negative sentiment. Datasets like IMDB movie reviews, Amazon product reviews, or SST-2 (Stanford Sentiment Treebank) provide labeled examples that make this problem well-suited for supervised learning. What makes sentiment analysis particularly interesting is that it requires understanding both word meaning and word order. For example:

  • “The movie was not bad.”
  • “The movie was bad.”

These two sentences contain almost identical tokens, but their sentiment differs due to the presence and placement of the word “not”. This highlights the importance of sequence modeling, where the model must track how words combine across time steps to express meaning. Recurrent neural networks (RNNs), especially LSTMs, are well-suited to this kind of task because they can retain context from earlier tokens as they process later ones. Unlike bag-of-words approaches or simple averaging of word embeddings, LSTMs treat the input as a sequence, allowing the model to build a representation of the entire sentence with attention to temporal dependencies.

In this lesson, we will construct a model that uses an LSTM layer to perform binary sentiment classification. We will also explore how the model's performance is affected by architectural and training choices, such as embedding type, hidden size, and dropout rate.

Preparing the Dataset

Before building the LSTM model, the text data must be transformed into a format suitable for training. Raw sentences cannot be fed directly into a neural network—they must first be tokenized, indexed, and padded to ensure consistent input shapes. These steps convert free-form text into numerical sequences the model can process efficiently.

The most commonly used benchmark for binary sentiment classification is the IMDB dataset, which contains 50,000 movie reviews split evenly between positive and negative labels. Other common datasets include SST-2 (for shorter, phrase-level sentiment) and Yelp reviews.

The preprocessing workflow typically involves the following:

  • Tokenization: Each sentence is split into a sequence of tokens (words or subwords). For simplicity, whitespace or rule-based tokenizers can be used, but modern implementations often rely on pretrained tokenizers that handle punctuation and special cases robustly.
  • Vocabulary Indexing: Each token is mapped to a unique integer using a vocabulary dictionary. Tokens not seen during training are mapped to a special <UNK> token. The resulting sentence is now a sequence of integers.
  • Padding and Truncation: Since LSTMs expect fixed-length input, all sequences are padded (or truncated) to a consistent max_length. Short sentences are padded with zeros at the end (or beginning), while longer sentences are truncated to avoid excessive memory usage.
# Example: padding a batch of 3 tokenized sentences to max length = 6
Input sequences (before padding):
["the movie was great", "i loved it", "boring"]

Padded (with zeros):
[[the, movie, was, great, 0, 0],
 [i, loved, it, 0, 0, 0],
 [boring, 0, 0, 0, 0, 0]]
  • Train-Validation Split: The dataset is divided into training and validation subsets (e.g., 80/20 split) to evaluate generalization during training.

These preprocessing steps are essential for ensuring compatibility between textual data and neural architectures. They also affect the model’s ability to generalize. For example, an overly small vocabulary can lead to high <UNK> rates, while excessive padding can waste memory and reduce convergence speed.

By the end of this phase, the input data will consist of fixed-length sequences of integers, ready to be embedded and passed through the LSTM layer.

Code: Preprocessing Text for LSTM Sentiment Classification (IMDB-style)

Before an LSTM model can process text data, the input must be transformed into numerical sequences of equal length. This code block demonstrates a typical preprocessing pipeline using PyTorch, including tokenization, vocabulary construction, sequence padding, and conversion to tensors. These steps are essential for preparing input suitable for batch processing and feeding into the model's embedding layer.

import torch
from torchtext.vocab import build_vocab_from_iterator
from torch.nn.utils.rnn import pad_sequence
from torch.utils.data import DataLoader
import re

# Example raw data (normally you'd load IMDB/SST2)
texts = ["The movie was great!", "I hated the ending.", "An average film."]
labels = [1, 0, 0]  # 1 = positive, 0 = negative

# Tokenization function
def tokenize(text):
    text = text.lower()
    text = re.sub(r"[^a-zA-Z0-9\s]", "", text)  # remove punctuation
    return text.strip().split()

# Tokenize all texts
tokenized_texts = [tokenize(t) for t in texts]

# Build vocabulary
def yield_tokens(data_iter):
    for tokens in data_iter:
        yield tokens

vocab = build_vocab_from_iterator(yield_tokens(tokenized_texts), specials=["<pad>", "<unk>"])
vocab.set_default_index(vocab["<unk>"])

# Numericalize tokenized text
numericalized = [torch.tensor(vocab(tokens)) for tokens in tokenized_texts]

# Pad sequences
padded = pad_sequence(numericalized, batch_first=True, padding_value=vocab["<pad>"])

# Labels as tensor
labels_tensor = torch.tensor(labels)

print("Padded Input:\n", padded)
print("Labels:\n", labels_tensor)

Explanation

  • Tokenizes the input text.
  • Builds a vocabulary from your dataset (with <pad> and <unk> tokens).
  • Numericalizes each sentence using the vocabulary.
  • Pads sequences to the longest sentence in the batch (you can later fix a max_length).
  • Returns tensors ready to be wrapped in a DataLoader.

Building the LSTM Classifier

Now that the input text has been tokenized, indexed, padded, and batched, the next step is to define the model architecture that will learn from these sequences. LSTM (Long Short-Term Memory) networks are ideal for sequence classification tasks because they retain temporal context across time steps, allowing the model to understand how word order influences meaning. For sentiment analysis, the model needs to process an input sentence and output a binary prediction indicating whether the sentiment is positive or negative. A typical architecture includes the following components:

  • Embedding layer: Maps token indices to dense vectors, optionally initialized with pre-trained embeddings.
  • LSTM layer: Processes the embedded sequence and learns hidden state transitions.
  • Dropout layer: Prevents overfitting by randomly zeroing activations during training.
  • Fully connected layer: Maps the final LSTM output to a scalar score.
  • Sigmoid activation: Converts the score into a probability between 0 and 1.

Code: LSTM Classifier in PyTorch

The following implementation shows how to define a basic LSTM-based sentiment classifier in PyTorch. The model includes an embedding layer, an LSTM block, dropout for regularization, and a fully connected layer that outputs a binary prediction through a sigmoid function. This structure is designed to handle fixed-length input sequences and return a probability of positive sentiment for each example.

import torch.nn as nn

class LSTMSentimentClassifier(nn.Module):
    def __init__(self, vocab_size, embedding_dim, hidden_dim, output_dim, padding_idx, num_layers=1, dropout=0.5):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embedding_dim, padding_idx=padding_idx)
        self.lstm = nn.LSTM(input_size=embedding_dim,
                            hidden_size=hidden_dim,
                            num_layers=num_layers,
                            batch_first=True)
        self.dropout = nn.Dropout(dropout)
        self.fc = nn.Linear(hidden_dim, output_dim)
        self.sigmoid = nn.Sigmoid()

    def forward(self, x):
        embedded = self.embedding(x)
        _, (hidden, _) = self.lstm(embedded)
        hidden = self.dropout(hidden[-1])  # Last layer's hidden state
        output = self.fc(hidden)
        return self.sigmoid(output)

Design Notes

  • vocab_size: total number of tokens in your vocabulary, including <pad> and <unk>.
  • padding_idx: ensures the embedding for the padding token remains zero and is not updated during training.
  • hidden[-1]: the final hidden state from the top LSTM layer is used for classification.
  • The model returns a single scalar output per example, passed through a sigmoid to represent the probability of the positive class.

This architecture is simple yet effective for binary classification tasks based on short to medium-length text.

While PyTorch offers a flexible, low-level way to define custom neural architectures, many teams use TensorFlow/Keras in production environments. Let’s now implement the same model using Keras’s Functional API, which offers more modularity and readability than its Sequential counterpart.

Code: LSTM Sentiment Classifier in Keras (Functional API)

The Functional API allows more control over the structure and naming of the model’s layers, while retaining the ability to mirror the same architecture as the PyTorch version. This version uses an embedding layer, a single LSTM unit, and a dense output layer with sigmoid activation for binary sentiment prediction.

from tensorflow.keras.models import Model
from tensorflow.keras.layers import Input, Embedding, LSTM, Dropout, Dense

input_seq = Input(shape=(200,), name="input_sequence")
x = Embedding(input_dim=10000, output_dim=128, input_length=200, name="embedding")(input_seq)
x = LSTM(64, dropout=0.2, recurrent_dropout=0.2, name="lstm")(x)
output = Dense(1, activation='sigmoid', name="output")(x)

model = Model(inputs=input_seq, outputs=output, name="LSTM_Sentiment_Classifier")
model.compile(loss='binary_crossentropy', optimizer='adam', metrics=['accuracy'])
model.summary()

This model structure is equivalent to the PyTorch implementation and is commonly used in Keras-based pipelines for text classification.

Training and Evaluation

Once the LSTM model has been defined, the next step is to train it on labeled data and evaluate its performance. For binary sentiment classification tasks, the most common setup includes:

  • Loss function: Binary cross-entropy, which penalizes incorrect predictions on binary targets.
  • Optimizer: Adam, which adapts the learning rate and typically converges faster than vanilla stochastic gradient descent.
  • Evaluation metric: Accuracy, which measures the percentage of correct predictions on the validation or test set.

The core strength of LSTMs lies in their ability to capture word order and context across time steps. Unlike bag-of-words models, which treat words independently, LSTMs learn to detect patterns like negation (“not bad”) or emphasis (“very good”) by examining token sequences as a whole. You don’t need to memorize the implementation details, but it’s important to understand the overall workflow:

  1. Text is tokenized and converted into indexed sequences.
  2. Sequences are padded or truncated to a consistent length.
  3. Each sequence is passed through the embedding layer and LSTM.
  4. The model learns which parts of the input are most predictive of sentiment.
  5. The output is a single probability representing the likelihood of positive sentiment.

This setup allows the model to adapt to complex language patterns and learn how structure influences meaning—making LSTMs a powerful tool for sequence-based tasks like sentiment analysis.

Hyperparameter Tuning

While LSTMs provide a powerful architecture for sequence modeling, their performance depends heavily on the choice of hyperparameters. These are settings that define the model structure and training behavior but are not learned from the data. Selecting the right configuration can significantly affect accuracy, convergence speed, and generalization. Some hyperparameters govern the architecture itself, such as the size of the hidden layer or the number of LSTM layers. Others affect the training process, like learning rate or batch size. There is no one-size-fits-all setting effective tuning requires experimentation and empirical validation. Below are key hyperparameters that influence LSTM performance in sentiment analysis.

Architectural Hyperparameters

These hyperparameters define the structure of the LSTM model itself—how much capacity it has to learn patterns in the data, and how it processes sequences. Adjusting these settings impacts the model’s ability to generalize, its training time, and how well it captures linguistic dependencies in text.

Embedding dimension: This defines the size of the vector used to represent each word. Larger dimensions allow the model to capture more semantic nuance, but they increase memory usage and risk overfitting if the dataset is small.

  • Common values: 100, 128, 300
  • Best practice: Start with 100 or 128 for most tasks, and only increase if you observe performance limitations.

LSTM Units (Hidden Dimension): This controls the number of memory cells (hidden units) in the LSTM layer. More units allow the model to learn more complex patterns but also increase the number of parameters and computational cost.

  • Typical values: 32, 64, 128, 256
  • Best practice: Start with 64 or 128, and scale up only if necessary based on validation performance. Monitor for signs of overfitting when using higher values.

Number of LSTM Layers: Adding more layers can increase the model’s capacity to learn hierarchical patterns in sequences. However, stacking LSTMs also increases training time and the risk of vanishing gradients.

  • Common values: 1 or 2
  • Use a single layer for most sentiment tasks unless deeper context modeling is needed.
  • Bidirectionality: A bidirectional LSTM processes the input sequence in both forward and backward directions, allowing the model to access both past and future context. This often improves performance in text classification and tagging tasks.
    • Best practice: Use bidirectional LSTMs when word context from both sides is important.
    • Consider disabling it in latency-sensitive applications or on very long sequences.

Training Hyperparameters

The following hyperparameters control how the model learns during training. While architecture defines what the model can represent, these settings influence how efficiently and effectively that representation is learned. Tuning them properly helps improve convergence, reduce overfitting, and optimize generalization.

Dropout and Recurrent Dropout: Dropout is a regularization method that randomly disables a fraction of the units in the network during training. This helps prevent overfitting by encouraging the model to learn more robust representations.

  • dropout: Applied to the input connections (e.g., from embedding to LSTM).
  • recurrent_dropout: Applied to the recurrent connections inside the LSTM cell.

These techniques are especially useful in small datasets or high-capacity models. Start with values like 0.2 for both and adjust based on validation performance.

Batch Size and Epochs: Batch size determines how many training samples are processed before the model updates its weights. Smaller batch sizes (e.g., 32 or 64) tend to improve generalization, while larger batches (e.g., 128) reduce training time but may lead to overfitting.

  • Common batch sizes: 32, 64, or 128
  • Larger batches enable faster computation but may learn less noise-resilient patterns.

Epochs define how many times the model will iterate over the entire training set. In most scenarios, 5 to 15 epochs are sufficient. It is best practice to monitor validation accuracy or loss and use early stopping to halt training once performance stops improving, this prevents unnecessary computation and reduces overfitting risk.

Learning rate: The learning rate controls the size of weight updates during backpropagation. If it's too high, the model may overshoot optimal values or fail to converge. If it's too low, training will be slow or may stall completely. Optimizers like Adam dynamically adjust the learning rate, but the initial value still matters. A good starting point is 0.001.

Sequence Length (Max Padding Length): This determines the fixed length of input sequences after padding or truncation. Longer sequences retain more context but increase memory usage and training time. For sentiment analysis, typical lengths range from 100 to 300 tokens.

Choose a length based on the average input size in your dataset and the nature of the task. For short reviews, 100–150 may suffice; for long-form input, 250–300 is more appropriate.

Practical Tip

Start with a simple configuration (e.g., 1 LSTM layer, 128 hidden units, 0.3 dropout) and monitor validation accuracy. Adjust one hyperparameter at a time to isolate its effect. Tools like Keras Tuner, Ray Tune, or manual grid search can help automate the tuning process when scaling up.

Hyperparameter tuning is a critical step toward improving model generalization and stability, especially in tasks involving subtle language patterns or imbalanced data.

Performance Evaluation

Once the model has been trained, the next step is to evaluate its performance. This involves more than just reporting accuracy; a meaningful evaluation considers whether the model generalizes well, how it behaves on unseen data, and whether its learning process was stable. For binary sentiment classification tasks, the primary evaluation metric is usually accuracy, which reflects the percentage of correctly predicted labels. However, it’s important to also monitor the loss curve and validation behavior over time.

Key Evaluation Indicators

Evaluating model performance is not limited to a final accuracy score. A robust evaluation involves tracking learning dynamics over time and analyzing multiple signals that reveal how well the model is generalizing to unseen data. The following indicators help diagnose overfitting, underfitting, and learning stability, and guide further improvements in model design or training setup.

  • Training vs. Validation Accuracy: A model that performs well on training data but poorly on validation data may be overfitting. Consistent accuracy across both sets indicates better generalization.
  • Loss Curves: Plotting the training and validation loss over each epoch provides insight into convergence. A steadily decreasing validation loss suggests the model is still learning. If validation loss increases while training loss decreases, overfitting is likely.
  • Precision, Recall, and F1 Score (optional for imbalanced data): While accuracy is appropriate for balanced sentiment datasets, other metrics like F1 score may be more informative when positive and negative labels are not evenly distributed.
  • Confusion Matrix: This provides a breakdown of true positives, false positives, true negatives, and false negatives. It helps identify systematic errors, such as confusing mildly negative reviews as positive.

Example: Interpreting Accuracy and Loss Curves

If your model achieves 89% accuracy on training data but only 83% on validation, it is likely memorizing patterns that do not generalize. In that case, consider:

  • Increasing dropout
  • Reducing LSTM units
  • Using early stopping
  • Gathering more training data

Performance metrics are not just numbers—they tell the story of how your model learns and where it might be going wrong.

Interpreting Learning Curves

Visualizing training and validation loss or accuracy over time provides important insight into the model's learning behavior. These learning curves help identify whether the model is underfitting, overfitting, or converging as expected. Here are common patterns and what they typically indicate.

1. Healthy Convergence

In a well-behaved training process, the model learns patterns that generalize to unseen data. This is typically reflected in the following trends:

  • Training loss decreases steadily — the model is fitting the training data effectively.
  • Validation loss follows a similar trend — it’s not just memorizing, but learning transferable patterns.
  • Gap between training and validation is small — suggesting strong generalization and minimal overfitting.

2. Overfitting

Overfitting occurs when the model begins to memorize training data rather than learn generalizable patterns. You’ll often notice these behaviors:

  • Training loss continues to decrease — showing continued memorization of training data.
  • Validation loss starts increasing after a few epochs — indicating that generalization is deteriorating.
  • Validation accuracy stagnates or declines — confirming reduced performance on unseen data.

3. Underfitting

Underfitting means the model lacks sufficient capacity or hasn’t been trained long enough to learn from the data. The following signs usually appear:

  • Both training and validation loss remain high — the model hasn't learned core patterns yet.
  • Little improvement over epochs — suggesting limited learning progress.
  • Accuracy is consistently low on both sets — confirming weak predictive ability.

4. Unstable Training

When training is unstable, the model's performance fluctuates unpredictably, often due to poor hyperparameter settings. This may look like:

  • Loss values fluctuate significantly — a sign of inconsistent learning.
  • Validation accuracy varies erratically — the model can’t settle on reliable patterns.
  • No clear downward trend — the optimization process is failing to converge.

This may be due to a learning rate that is too high, insufficient batch size, or noisy data. Try lowering the learning rate or smoothing the input.

Learning curves are a visual feedback loop, use them to detect problems early, guide hyperparameter tuning, and validate training progress. When loss curves reveal signs of overfitting such as rising validation loss and a widening gap from training performance, it’s important to apply corrective techniques. The following section outlines common strategies to prevent overfitting and improve generalization.

Understanding and Preventing Overfitting

Overfitting occurs when a model learns patterns in the training data too precisely including noise and irrelevant details leading to poor generalization on unseen inputs. It is often detected by a widening gap between training and validation accuracy or by steadily increasing validation loss while training loss continues to decrease. To mitigate overfitting and improve generalization, the following strategies are commonly used:

  1. Dropout: Dropout randomly disables a fraction of the input units during training. This prevents the model from relying too heavily on any single neuron and encourages it to learn more distributed, robust representations.
  2. Early Stopping: Early stopping monitors validation performance during training and halts training when the model stops improving. This avoids unnecessary training epochs that may lead to overfitting.
    from tensorflow.keras.callbacks import EarlyStoppingearly_stop = EarlyStopping(monitor='val_loss', patience=2)model.fit(X_train, y_train, validation_data=(X_val, y_val), callbacks=[early_stop])
  3. Smaller Model Capacity: Reducing the number of LSTM units or layers lowers the model’s representational capacity, making it less likely to memorize noise in the training set. Start small and increase capacity only if underfitting is observed.
  4. L2 Regularization: Also known as weight decay, L2 regularization penalizes large weight values by adding a regularization term to the loss function. This constrains the model to learn simpler functions.
    from tensorflow.keras.regularizers import l2Dense(64, activation='relu', kernel_regularizer=l2(0.01))
  5. Pre-trained Embeddings: Using pre-trained embeddings such as GloVe or FastText provides a strong inductive bias by encoding general semantic relationships. This is especially helpful on small datasets, where learning embeddings from scratch may lead to overfitting.

These techniques help ensure that the model performs not only well on the training data, but also generalizes effectively to new, real-world inputs.
